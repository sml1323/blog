# 데코레이터를 사용한 코드 개선

## 파이썬의 데코레이터

파이썬의 함수는 일반적인 객체로서 변수에 할당되거나 파라미터로 전달되거나, 다른 함수 내에서 호출될 수 있다.

- 함수를 변형하기 위해 `modifier`를 호출하고, 기존 함수와 같은 방식으로 저장하는 방법:

  ```python
  def original(...):
      ...
  original = modifier(original)
  ```

- 데코레이터 사용:

  ```python
  @modifier
  def original(...):
      ...
  ```

> 여기서 `modifier`를 파이썬 용어로 **데코레이터**라고 하고, `original`을 **데코레이팅된 함수** 또는 **wrapped 객체**라고 한다.  
> 데코레이터는 데코레이터 이후에 나오는 대상을 첫 번째 인자로 받아, 데코레이터의 결과값으로 반환하는 문법적 설탕(syntactic sugar)이다.

### 데코레이터 기본 골격

```python
from functools import wraps

def my_decorator(original_function):  # 1️⃣ 원래 함수를 매개변수로 받음
    @wraps(original_function)         # 2️⃣ 원래 함수의 메타데이터 유지
    def wrapped_function(*args, **kwargs):  # 3️⃣ 실제로 감싸는 함수
        # 여기에서 추가 동작을 수행할 수 있음
        return original_function(*args, **kwargs)  # 원래 함수 실행
    return wrapped_function  # 감싼 함수 반환
```

💡 이 구조를 사용하면 **원래 함수의 기능을 유지하면서 추가 기능을 넣을 수 있다.**  
`@wraps(original_function)`을 사용하면 원래 함수의 `__name__`, `__doc__` 등 메타데이터가 유지.

## 함수 데코레이터

```python
# decorator_function_1.py
class ControlledException(Exception):
    """도메인에서 발생하는 일반적인 예외"""

def retry(operation):
    @wraps(operation)
    def wrapped(*args, **kwargs):
        last_raised = None
        RETRIES_LIMIT = 3
        for _ in range(RETRIES_LIMIT):
            try:
                return operation(*args, **kwargs)
            except ControlledException as e:
                print(f"다음과 같은 예외가 발생했습니다: {e}")
                last_raised = e
        raise last_raised
    return wrapped

@retry
def run_operation(task):
    """실행 중 예외가 발생할 것으로 예상되는 특정 작업을 실행"""
    return task.run()
```

## 클래스 데코레이터

- 클래스 역시 객체이다.
- 클래스 데코레이터를 사용하면 코드 재사용과 DRY 원칙의 이점을 얻을 수 있으며, 여러 클래스가 특정 인터페이스나 기준을 따르도록 강제할 수 있다.
- 작고 간단한 클래스를 생성한 후, 데코레이터로 기능을 보강할 수 있다.

**각 이벤트마다 직렬화 방법을 정의한 클래스 예시:**

```python
from dataclasses import dataclass
from datetime import datetime

def hide_field(field) -> str:
    return "**redacted**"

def format_time(field_timestamp: datetime) -> str:
    return field_timestamp.strftime("%Y-%m-%d %H:%M")

def show_original(event_field):
    return event_field

class EventSerializer:
    def __init__(self, serialization_fields: dict) -> None:
        self.serialization_fields = serialization_fields

    def serialize(self, event) -> dict:
        return {
            field: transformation(getattr(event, field))
            for field, transformation in self.serialization_fields.items()
        }

class Serialization:
    
    def __init__(self, **transformations):
        self.serializer = EventSerializer(transformations)
    
    def __call__(self, event_class):
        def serialize_method(event_instance):
            return self.serializer.serialize(event_instance)
        event_class.serialize = serialize_method
        return event_class

@Serialization( 
    username=str.lower, 
    password=hide_field, 
    ip=show_original, 
    timestamp=format_time, 
) 
@dataclass 
class LoginEvent: 
    username: str 
    password: str 
    ip: str 
    timestamp: datetime
```

### 설명

이 코드는 데코레이터를 사용하여 데이터 클래스에 **직렬화(serialization)** 기능을 추가하는 방법을 보여준다.  
`Serialization` 데코레이터는 `EventSerializer`를 사용하여 데이터 클래스의 인스턴스를 딕셔너리로 변환하며, 각 필드는 지정된 변환 함수를 통해 처리된다. 이를 통해 민감한 정보를 숨기거나 날짜 형식을 변경하는 등 다양한 방식으로 데이터를 직렬화할 수 있다.  
`LoginEvent` 클래스는 이러한 직렬화 데코레이터의 사용 예시를 보여준다.

#### 함수 설명

1. **`hide_field(field) -> str`**
   - **목적:** 주어진 필드 값을 숨긴다.
   - **동작:** 입력된 필드 값과 상관없이 항상 `"**redacted**"` 문자열을 반환한다.
   
2. **`format_time(field_timestamp: datetime) -> str`**
   - **목적:** `datetime` 객체를 `"YYYY-MM-DD HH:MM"` 형식의 문자열로 변환한다.
   - **동작:** `strftime` 메서드를 사용하여 날짜/시간을 지정된 형식으로 변환한다.
   
3. **`show_original(event_field)`**
   - **목적:** 입력된 값을 그대로 반환한다.
   - **동작:** 어떠한 변환도 적용하지 않고 원래 값을 유지한다.

#### 클래스 설명

1. **`EventSerializer`**
   - **목적:** 이벤트 객체를 딕셔너리로 직렬화한다.
   - **주요 메서드:**
     - `serialize(self, event) -> dict`: `serialization_fields`에 정의된 필드와 변환 함수를 사용하여 이벤트 객체의 각 필드를 직렬화한다.
   
2. **`Serialization`**
   - **목적:** 데코레이터로 사용되어 데이터 클래스에 직렬화 기능을 추가한다.
   - **주요 메서드:**
     - `__call__(self, event_class)`: 데이터 클래스에 `serialize` 메서드를 추가한다.
   
3. **`LoginEvent`**
   - **목적:** 직렬화 데코레이터의 사용 예시를 보여주는 데이터 클래스이다.
   - **동작:**  
     `@Serialization` 데코레이터가 적용되어 `serialize` 메서드를 갖게 되며,  
     - `username`은 소문자로 변환,  
     - `password`는 `"**redacted**"`로 숨겨지고,  
     - `ip`는 원래 값 그대로,  
     - `timestamp`는 지정된 형식의 문자열로 변환된다.

#### 사용 예시

```python
from dataclasses import dataclass
from datetime import datetime

def hide_field(field) -> str:
    return "**redacted**"

def format_time(field_timestamp: datetime) -> str:
    return field_timestamp.strftime("%Y-%m-%d %H:%M")

def show_original(event_field):
    return event_field

class EventSerializer:
    def __init__(self, serialization_fields: dict) -> None:
        self.serialization_fields = serialization_fields

    def serialize(self, event) -> dict:
        return {
            field: transformation(getattr(event, field))
            for field, transformation in self.serialization_fields.items()
        }

class Serialization:
    def __init__(self, **transformations):
        self.serializer = EventSerializer(transformations)

    def __call__(self, event_class):
        def serialize_method(event_instance):
            return self.serializer.serialize(event_instance)
        event_class.serialize = serialize_method
        return event_class

@Serialization(
    username=str.lower,
    password=hide_field,
    ip=show_original,
    timestamp=format_time,
)
@dataclass
class LoginEvent:
    username: str
    password: str
    ip: str
    timestamp: datetime

event = LoginEvent(
    username="UserNAME",
    password="SecretPassword",
    ip="127.0.0.1",
    timestamp=datetime(2023, 10, 27, 11, 0, 0)
)

serialized_event = event.serialize()
print(serialized_event)
# Expected Output:
# {'username': 'username', 'password': '**redacted**', 'ip': '127.0.0.1', 'timestamp': '2023-10-27 11:00'}
```

## 고급 데코레이터

### 데코레이터에 인자 전달

데코레이터에 파라미터를 전달하기 위해서는 **간접 참조(indirection)**를 사용하여 추가적인 중첩 함수를 만들어야 한다.

#### 중첩 함수를 사용한 데코레이터

- 고차 함수(higher-order function)처럼 데코레이터는 함수를 파라미터로 받아서 함수를 반환한다.
- 데코레이터에 파라미터를 추가하려면 또 다른 중첩 함수가 필요하다.
  
예를 들어:

```python
@retry(arg1, arg2, ...)
```

는 내부적으로 아래와 같이 동작한다:

```python
<original_function> = retry(arg1, arg2, ...)(<original_function>)
```

- 재시도 횟수 외에도 제어하려는 예외 유형을 지정할 수도 있다.

```python
DEFAULT_RETRIES_LIMIT = 3

def with_retry(
    retries_limit: int = DEFAULT_RETRIES_LIMIT,
    allowed_exceptions: Optional[Sequence[Exception]] = None,
):
    allowed_exceptions = allowed_exceptions or (ControlledException,)  # type: ignore
    def retry(operation):
        @wraps(operation)
        def wrapped(*args, **kwargs):
            last_raised = None
            for _ in range(retries_limit):
                try:
                    return operation(*args, **kwargs)
                except allowed_exceptions as e:
                    logger.warning("retrying %s due to %s", operation.__qualname__, e)
                    last_raised = e
            raise last_raised
        return wrapped
    return retry

# decorator_parametrized_1.py
@with_retry()
def run_query(task):
    return task.run()

@with_retry(retries_limit=5)
def run_with_custom_retries_limit(task):
    return task.run()

@with_retry(allowed_exceptions=(AttributeError,))
def run_with_custom_exceptions(task):
    return task.run()

@with_retry(retries_limit=4, allowed_exceptions=(ZeroDivisionError, AttributeError))
def run_with_custom_parameters(task):
    return task.run()
```

#### 데코레이터 객체

클래스를 사용하여 데코레이터를 정의할 수도 있다.  
`__init__` 메서드에 파라미터를 전달하고, `__call__` 메서드에서 데코레이터 로직을 구현한다.

```python
_DEFAULT_RETRIES_LIMIT = 3

class WithRetry:
    def __init__(
        self,
        retries_limit: int = _DEFAULT_RETRIES_LIMIT,
        allowed_exceptions: Optional[Sequence[Exception]] = None,
    ) -> None:
        self.retries_limit = retries_limit
        self.allowed_exceptions = allowed_exceptions or (ControlledException,)

    def __call__(self, operation):
        @wraps(operation)
        def wrapped(*args, **kwargs):
            last_raised = None
            for _ in range(self.retries_limit):
                try:
                    return operation(*args, **kwargs)
                except self.allowed_exceptions as e:
                    logger.warning("retrying %s due to %s", operation.__qualname__, e)
                    last_raised = e
            raise last_raised
        return wrapped
```

#### 기본값을 가진 데코레이터

```python
@decorator(x=3, y=4)
def my_function():
    return x + y

my_function()
```

위 코드는 데코레이터에 기본값이 들어 있기 때문에 함수의 인자가 없어도 호출할 수 있다.

```python
def decorator(function=None, *, x=DEFAULT_X, y=DEFAULT_Y):
    if function is None:
        # `@decorator(...)` 형태로 호출한 경우
        def decorated(function):
            @wraps(function)
            def wrapped():
                return function(x, y)
            return wrapped
        return decorated
    else:
        # `@decorator` 형태로 호출한 경우
        @wraps(function)
        def wrapped():
            return function(x, y)
        return wrapped
```

또는 람다를 사용해 간결하게 작성할 수도 있다.

```python
def decorator(function=None, *, x=DEFAULT_X, y=DEFAULT_Y):
    if function is None:
        return lambda f: decorator(f, x=x, y=y)

    @wraps(function)
    def wrapped():
        return function(x, y)
    return wrapped
```

> 위 코드는 함수가 제공되지 않으면 함수를 인자로 받아서 나머지 파라미터와 함께 재귀적으로 `decorator` 함수를 다시 호출하는 lambda를 반환한다.

## 데코레이터 활용 우수 사례

### 함수 서명 변경

원래 코드:

```python
def resolver_function(root, args, context, info):
    helper = DomainObject(root, args, context, info)
    helper.process()
```

변경 후:

```python
from functools import wraps

def DomainArgs(function):
    @wraps(function)
    def wrapped_function(root, args, context, info):
        helper = DomainObject(root, args, context, info)
        return function(helper)
    return wrapped_function

@DomainArgs
def resolver_function(helper):
    helper.process()
```

### 래핑된 원본 객체의 데이터 보존

원래 로그를 남기는 데코레이터:

```python
def trace_decorator(function):
    def wrapped(*args, **kwargs):
        logger.info("%s 실행", function.__qualname__)
        return function(*args, **kwargs)
    return wrapped
```

이 경우, 원본 함수의 메타데이터(`__name__`, `__doc__` 등)가 보존되지 않아 개별 함수에 대한 로깅이 어려워질 수 있다.  
따라서 `functools.wraps`를 사용하여 메타데이터를 유지해야 한다.

수정된 코드:

```python
def trace_decorator(function):
    @wraps(function)
    def wrapped(*args, **kwargs):
        logger.info("%s 실행", function.__qualname__)
        return function(*args, **kwargs)
    return wrapped
```

> **항상 데코레이터를 만들 때는 래핑된 함수 위에 `@wraps`를 사용하여 원본 함수의 정보를 유지해야 한다.**

## 데코레이터 부작용 처리

잘못 정의된 데코레이터 예시:

```python
import time
from functools import wraps
import logging

def traced_function_wrong(function):
    """잘못 정의된 데코레이터의 예시."""
    logging.info("started execution of %s", function)
    start_time = time.time()

    @wraps(function)
    def wrapped(*args, **kwargs):
        result = function(*args, **kwargs)
        logging.info("function %s took %.2fs", function, time.time() - start_time)
        return result

    return wrapped

@traced_function_wrong
def process_with_delay(callback, delay=0):
    time.sleep(delay)
    return callable()
```

### 문제점

1. **데코레이터 적용 시점에 로그가 찍힘**  
   `logging.info("started execution of %s", function)`가 데코레이터가 적용될 때(즉, 프로그램이 실행되기 전에) 실행되어 함수 호출 이전에 로그가 남는다.
   
2. **`start_time`이 잘못 저장됨**  
   `start_time = time.time()`이 데코레이터가 처음 실행될 때 한 번만 저장되므로, 매 함수 호출마다 새로운 실행 시간을 측정할 수 없다.

### 해결 방법

- `logging.info(...)`와 `start_time`은 **함수가 실행될 때마다** 계산되도록 `wrapped()` 내부로 옮긴다.

## 어느 곳에서나 동작하는 데코레이터 만들기

`@inject_db_driver` 데코레이터를 `DataHandler.run_query`에 적용할 때 발생하는 문제와 해결 방법

### 1️⃣ `@inject_db_driver`의 동작 방식

```python
def inject_db_driver(function):
    """파라미터로 전달받은 데이터베이스 DNS 문자열을 사용하여 DBDriver 인스턴스 생성"""

    @wraps(function)
    def wrapped(dbstring):  # dbstring을 받음
        return function(DBDriver(dbstring))  # DBDriver 인스턴스를 생성하여 넘김
    return wrapped
```

- **동작 요약:**
  - 문자열(`dbstring`)을 인자로 받아 `DBDriver(dbstring)` 객체로 변환하고,
  - 변환된 객체를 `function(driver: DBDriver)`에 전달한다.

### 2️⃣ `run_query` 함수에서는 동작하는 이유

```python
@inject_db_driver
def run_query(driver):
    return driver.execute("test_function")
```

- **설명:**
  - `run_query`는 **DBDriver 객체 하나**를 인자로 받으므로,  
    `run_query("my_database")`처럼 문자열을 전달하면 데코레이터가 이를 `DBDriver` 객체로 변환하여 올바르게 호출된다.

### 3️⃣ `DataHandler.run_query`에서는 동작하지 않는 이유

```python
class DataHandler:
    @inject_db_driver
    def run_query(self, driver):
        return driver.execute(self.__class__.__name__)
```

- **문제점:**
  - 인스턴스 메서드는 항상 첫 번째 인자로 `self`를 받는다.
  - 하지만 `inject_db_driver`는 첫 번째 인자를 `dbstring`이라고 가정하고 있으므로,  
    `self`가 `dbstring`으로 잘못 처리되어 오류가 발생한다.

### 4️⃣ 수정 방법

#### (1) `inject_db_driver`를 인스턴스 메서드에 맞게 수정

```python
def inject_db_driver(function):
    """파라미터로 전달받은 데이터베이스 DNS 문자열을 사용하여 DBDriver 인스턴스 생성"""

    @wraps(function)
    def wrapped(self, dbstring):  # self를 포함하도록 수정
        return function(self, DBDriver(dbstring))  # self와 함께 DBDriver 객체를 전달
    return wrapped
```

#### (2) 수정된 `DataHandler` 클래스

```python
class DataHandler:
    @inject_db_driver
    def run_query(self, driver):
        return driver.execute(self.__class__.__name__)
```

이제 다음과 같이 정상 실행된다.

```python
handler = DataHandler()
print(handler.run_query("my_database"))  # 정상 실행
```

### 5️⃣ 정리

- **문제 원인:**  
  `inject_db_driver`는 첫 번째 인자가 문자열(`dbstring`)이라고 가정했으나, 인스턴스 메서드는 첫 번째 인자로 `self`를 받아야 하므로 오류 발생.
  
- **해결 방법:**  
  `wrapped(self, dbstring)` 형태로 수정하여 `self`를 유지하고,  
  `function(self, DBDriver(dbstring))`를 호출하여 올바르게 DBDriver 객체를 전달한다.
