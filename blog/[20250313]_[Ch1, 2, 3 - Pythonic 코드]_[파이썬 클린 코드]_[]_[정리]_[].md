# Chapter 1. 서론

<details>
  <summary>`attribute` vs. `property`의 차이</summary>

| 개념                      | 설명                                                         | 예시                                                        |
| ------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| **Attribute (일반 속성)** | 클래스의 **변수(필드)**로, 값이 직접 저장됨.               | `obj.name = "Alice"`                                        |
| **Property (프로퍼티)**   | 속성처럼 보이지만, **getter, setter 등을 활용한 메서드 기반 속성** | `obj.age = 30  # 내부적으로 setter 메서드 실행`              |

### Getter, Setter 사용 예제

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self._age = age  # 진짜 값은 _age에 저장 (보호를 위해 _ 사용)

    @property
    def age(self):
        """getter 역할: 값을 가져올 때 호출됨"""
        print("getter 호출됨")
        return self._age

    @age.setter
    def age(self, value):
        """setter 역할: 값을 변경할 때 호출됨"""
        print("setter 호출됨")
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person("Alice", 30)

print(p.age)  # getter 호출됨 → 30
p.age = 35    # setter 호출됨
print(p.age)  # getter 호출됨 → 35
```

---

## ✅ `@property`를 사용하는 4가지 주요 장점

### 1️⃣ 캡슐화 (Encapsulation) - 내부 구현을 숨길 수 있음

일반 속성(`self.age`)을 직접 사용하면, 속성의 내부 구조가 변경될 때 코드를 수정해야 할 수도 있음.

#### ❌ 일반 속성을 사용하면?

```python
class Person:
    def __init__(self, age):
        self.age = age  # 그냥 속성

p = Person(30)
print(p.age)  # 30
p.age = -5    # 잘못된 값이 들어감! (문제 발생)
```

위 코드에서는 `p.age = -5`처럼 **잘못된 값**을 막을 방법이 없음.

---

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, age):
        self._age = age  # 실제 값은 _age에 저장

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person(30)
p.age = -5  # ❌ ValueError 발생! (잘못된 값 차단)
```

✔️ **외부에서 직접 `self._age`에 접근하지 못하게 하고, setter를 통해 제어하는 방식!**

---

### 2️⃣ 인터페이스 유지 - 내부 구현을 바꿔도 외부 코드는 그대로 유지됨

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, birth_year):
        self._birth_year = birth_year  # 출생 연도를 저장

    @property
    def age(self):
        """현재 연도(2024)에서 출생 연도를 빼서 나이 계산"""
        return 2024 - self._birth_year

p = Person(1994)
print(p.age)  # 30  (출생 연도 기반 계산)
```

✔️ **속성 이름(`age`)을 그대로 유지하면서 내부 구현을 바꿀 수 있음!**

---

### 3️⃣ 동적 계산 가능 (Lazy Evaluation)

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        """넓이를 매번 계산하여 반환"""
        return self.width * self.height

r = Rectangle(5, 10)
print(r.area)  # 50  (속성처럼 보이지만 실제로는 메서드 실행)
```

✔️ **데이터를 저장하지 않고, 필요할 때마다 계산할 때 유용!**

---

### 4️⃣ 읽기 전용 속성 만들기 가능 (Setter 없이 Getter만 사용)

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def diameter(self):
        """지름은 반지름의 2배이며, 변경할 수 없음"""
        return self._radius * 2

c = Circle(10)
print(c.diameter)  # 20
c.diameter = 30    # ❌ AttributeError: can't set attribute (setter가 없으므로 수정 불가)
```

✔️ **읽기 전용 속성이 필요할 때 getter만 사용하면 됨.**

## 최종 정리

| 장점                 | 설명                                     |
| -------------------- | ---------------------------------------- |
| **캡슐화**           | 내부 속성을 보호하고, setter를 통해 제어 가능 |
| **인터페이스 유지**  | 내부 구현이 바뀌어도 외부 코드 수정 없이 유지 가능 |
| **동적 계산**        | 속성을 저장하지 않고, 필요할 때마다 계산 가능 |
| **읽기 전용 속성**   | setter 없이 getter만 사용하여 변경 불가능하게 만들 수 있음 |

## 02. 문서화 - Documentation

### 코드 주석 (Code Comments)

- 가능한 적은 주석을 사용하는 것이 목표.
- **좋은 코드는 코드 자체가 문서화되어 있음.**
- 주석은 코드를 올바르게 작성하지 않았다는 신호일 수 있음.
- 문서화는 코드 설계 방식이나 아키텍처를 설명하는 것으로, 긍정적인 효과를 가져옴.

### Docstring

- **Docstring:** 소스코드에 포함된 문서. 주석과 달리 **문서** 역할을 함.
- 함수의 파라미터나 반환값의 데이터 타입 등을 설명할 때 유용.
- 파이썬은 동적 타입 언어이므로, Docstring을 통해 추가적인 타입 정보를 제공할 수 있음.

### 어노테이션 (Annotation)

- 함수 인자에 어떤 값이 와야 하는지 힌트를 제공.
- 예제: 변수의 예상 타입 지정

```python
@dataclass
class Point:
    lat: float
    long: float

def locate(latitude: float, longitude: float) -> Point:
    """맵에서 좌표에 해당하는 객체를 검색"""
```

- **예시:** `def launch_task(delay: Seconds):`에서 `Seconds` 어노테이션을 사용해 시간을 어떻게 해석할지 추상화 가능.
- 함수의 `__annotations__` 속성을 통해 타입 정보를 확인할 수 있음.

```python
locate.__annotations__
# {'latitude': <class 'float'>, 'longitude': <class 'float'>, 'return': <class '__main__.Point'>}
```

- Docstring과 어노테이션은 서로 보완적인 관계임.

### 이터러블과 시퀀스

#### 이터러블 객체

- `list`, `tuple`, `set`, `dict` 등은 for 루프를 통해 반복 가능함.
- 이터러블은 `__iter__` 매직 메서드를 구현해야 하며, 이터레이터는 `__next__` 메서드를 구현함.

#### 이터러블 예제: 날짜를 하루 간격으로 반복

```python
from datetime import timedelta, datetime

class DateRangeIterable:
    """자체 이터레이터 메서드를 가진 이터러블"""
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date
        self._present_day = start_date

    def __iter__(self):
        return self

    def __next__(self):
        if self._present_day >= self.end_date:
            raise StopIteration
        today = self._present_day
        self._present_day += timedelta(days=1)
        return today

for day in DateRangeIterable(datetime(2019, 1, 1), datetime(2019, 1, 5)):
    print(day)
```

> **주의:** 한 번 순회하면 _present_day가 종료 상태가 되어, 재사용할 수 없음.

#### 제너레이터를 활용한 이터러블

```python
from datetime import timedelta, datetime

class DateRangeIterable:
    """제너레이터를 사용한 이터러블"""
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date

    def __iter__(self):
        present_day = self.start_date
        while present_day < self.end_date:
            yield present_day
            present_day += timedelta(days=1)

# 여러 번 사용 가능
dates = DateRangeIterable(datetime(2019, 1, 1), datetime(2019, 1, 5))

for day in dates:
    print(day)

print("두 번째 루프 실행!")

for day in dates:
    print(day)
```

#### 시퀀스 객체

- `__len__`과 `__getitem__` 메서드를 구현하여 인덱싱과 반복을 지원.
- 메모리 사용량과 인덱싱 시간의 트레이드 오프가 있음.

```python
from datetime import timedelta, datetime

class DateRangeSequence:
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date
        self._range = self._create_range()

    def _create_range(self):
        days = []
        current_day = self.start_date
        while current_day < self.end_date:
            days.append(current_day)
            current_day += timedelta(days=1)
        return days

    def __getitem__(self, day_no):
        return self._range[day_no]

    def __len__(self):
        return len(self._range)

s1 = DateRangeSequence(datetime(2021, 1, 1), datetime(2021, 1, 5))
for day in s1:
    print(day)

print(s1[3])
```

## 컨테이너 객체

- **컨테이너:** `__contains__` 메서드를 구현한 객체. `in` 키워드 사용 시 호출됨.

```python
class Boundaries:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def __contains__(self, coord):
        x, y = coord
        return 0 <= x < self.width and 0 <= y < self.height

class Grid:
    def __init__(self, width, height):
        self.width = width
        self.height = height
        self.limits = Boundaries(width, height)
    
    def __contains__(self, coord):
        return coord in self.limits

def mark_coordinate(grid, coord):
    if coord in grid:
        grid[coord] = "MARKED"
```

## 객체의 동적인 속성

- `__getattr__` 메서드를 사용하면 존재하지 않는 속성 접근 시 동작을 정의할 수 있음.
- 속성이 존재하면 `__dict__`에서 반환되고, 없으면 `__getattr__`이 호출됨.

```python
class DynamicAttributes:
    def __init__(self, attribute):
        self.attribute = attribute

    def __getattr__(self, attr):
        if attr.startswith("fallback_"):
            name = attr.replace("fallback_", "")
            return f"[fallback resolved] {name}"
        raise AttributeError(f"{self.__class__.__name__}에는 {attr} 속성이 없습니다.")

dyn = DynamicAttributes("value")
print(dyn.attribute)          # 일반 속성 출력
print(dyn.fallback_test)      # [fallback resolved] test

# __dict__에 직접 값을 넣으면 __getattr__이 호출되지 않음
dyn.__dict__["fallback_test"] = "new value"
print(getattr(dyn, "fallback_test"))    # new value
print(getattr(dyn, "fallback_test2"))   # [fallback resolved] test2
```

## 호출형 객체 (Callable)

- 객체를 함수처럼 호출하면 `__call__` 메서드가 실행됨.

```python
from collections import defaultdict

class CallCount:
    def __init__(self):
        self._counts = defaultdict(int)

    def __call__(self, argument):
        self._counts[argument] += 1
        return self._counts[argument]

cc = CallCount()
print(cc(1))  # -> 1
print(cc(1))  # -> 2
print(cc(2))  # -> 1
```

### 변경 가능한 (mutable) 파라미터의 기본 값

```python
def wrong_user_display(user_metadata: dict = {"name": "John", "age": 30}):

    age = user_metadata.pop("age")

```

- **해결 방법:** 기본값을 `None`으로 설정한 후 함수 내에서 초기화

```python
def correct_user_display(user_metadata: dict = None):
    user_metadata = user_metadata or {"name": "John", "age": 30}
    name = user_metadata.pop("name")
    age = user_metadata.pop("age")
    return f"{name} is {age} years old"
```

# Chapter 3. 좋은 코드의 일반적인 특징

## 계약에 의한 디자인 (Design by Contract)

- 컴포넌트는 내부 기능을 캡슐화하고, 클라이언트에게 API를 제공해야 함.
- **계약에 의한 디자인:** 사전조건, 사후조건, 불변식, 부작용 등을 명시하여 계약을 어겼을 때 명시적으로 예외 발생

## 방어적 프로그래밍

> 객체나 함수가 스스로 유효하지 않은 상태로부터 보호할 수 있도록 작성하는 방식

### 에러 핸들링

- **목적:** 예상되는 에러를 처리하여 실행을 계속하거나, 극복할 수 없는 경우 프로그램 중단
  - **값 대체 (value substitution)**
  - **에러 로깅**
  - **에러 처리**

### 예외 처리

- **예외 처리:** 함수나 메서드 내에서 예외 상황을 명확히 하고, 비즈니스 로직의 흐름을 유지
- **올바른 추상화 단계:** 함수는 하나의 역할에 집중해야 하며, 예외는 해당 함수의 로직에 맞게 처리

#### `DataTransport` 클래스 예제

```python
import time
import logging
from typing import Protocol

logger = logging.getLogger(__name__)

class Connector(Protocol):
    def connect(self):
        ...

class Event(Protocol):
    def decode(self):
        ...

class DataTransport:
    """다양한 수준의 예외를 처리하는 예"""
    _RETRY_BACKOFF: int = 5
    _RETRY_TIMES: int = 3

    def __init__(self, connector: Connector) -> None:
        self._connector = connector
        self.connection = None

    def deliver_event(self, event: Event):
        try:
            self.connect()  # 서버에 연결 시도
            data = event.decode()  # 이벤트 데이터 디코딩
            self.send(data)  # 데이터 전송
        except ConnectionError as e:
            logger.info("커넥션 오류 발견: %s", e)
            raise  # 예외 재전달
        except ValueError as e:
            logger.error("%r 이벤트에 잘못된 데이터 포함: %s", event, e)
            raise

    def connect(self):
        for _ in range(self._RETRY_TIMES):
            try:
                self.connection = self._connector.connect()
            except ConnectionError as e:
                logger.info("%s: 새로운 커넥션 시도 %is", e, self._RETRY_BACKOFF)
                time.sleep(self._RETRY_BACKOFF)
            else:
                return self.connection
        raise ConnectionError(f"{self._RETRY_TIMES} 번의 재시도 모두 실패")

    def send(self, data: bytes):
        return self.connection.send(data)
```

### 예외 처리 동작 방식

1. **`deliver_event()`**
   - `connect()`로 서버에 연결 시도
   - `event.decode()`로 데이터 디코딩
   - `send(data)`로 전송
   - 예외 발생 시 적절한 로깅 후 상위로 예외 전달

2. **`connect()`**
   - 최대 `_RETRY_TIMES` (3회)까지 재시도
   - 실패 시 `ConnectionError` 발생

3. **`send()`**
   - 단순 전송, 예외 처리는 상위 메서드에서 수행
