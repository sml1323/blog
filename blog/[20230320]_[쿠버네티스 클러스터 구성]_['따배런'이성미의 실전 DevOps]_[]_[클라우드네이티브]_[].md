## 1. Kubernetes 클러스터 준비: 사전 준비 작업 (모든 노드에서 수행)

### 시스템 정보 확인 및 기본 요구사항 체크

- **OS 정보 확인**:
    
    ```bash
    cat /etc/os-release
    
    ```
    
    이 명령어로 현재 설치된 Ubuntu 버전을 확인합니다.
    
- **하드웨어 요구사항**:
    - 최소 2GB 이상의 RAM과 2개 이상의 CPU를 확보해야 합니다.
    
    ```bash
    lscpu
    free -h
    
    ```
    
- **네트워크 설정**:
    - 모든 노드가 완전한 네트워크 연결 상태여야 하며, 각 노드의 호스트명, IP, /etc/hosts 파일이 올바르게 설정되어야 합니다.
    - 예시로 `/etc/hosts`에 각 노드의 IP와 이름이 매핑되어 있는지 확인합니다.
- **방화벽 설정**:
    - 필요시 ufw(방화벽)를 비활성화 하거나, 클러스터 간 통신에 필요한 포트를 열어줍니다.
- **스왑(Swap) 비활성화**:
    - Kubernetes의 kubelet은 스왑이 활성화된 경우 제대로 동작하지 않으므로 스왑을 비활성화 합니다.
    
    ```bash
    swapoff -a && sed -i '/swap/s/^/#/' /etc/fstab
    swapon -s
    
    ```

## 2. 컨테이너 런타임(Containerd) 설치 (모든 노드에서 수행)

컨테이너 런타임은 Kubernetes에서 실제 컨테이너를 실행하는 역할을 담당합니다. 여기서는 **containerd**를 설치합니다.

### 설치 과정

1. **필요 패키지 설치**:
    - HTTPS를 통한 저장소 접근을 위해 필요한 패키지들을 설치합니다.
    
    ```bash
    apt update
    apt install apt-transport-https ca-certificates curl gnupg lsb-release -y
    
    ```
    
2. **Docker 공식 GPG 키 추가 및 저장소 등록**:
    - Docker의 GPG 키를 추가하여 신뢰할 수 있는 저장소로 설정한 후 Docker 저장소를 등록합니다.
    
    ```bash
    curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

    echo "deb [arch=amd64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null


    apt update
    
    ```
    
3. **Docker 및 Containerd 설치**:
    - Docker와 containerd 및 관련 플러그인들을 설치합니다.
    
    ```bash
    apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin -y
    
    docker version
    
    ```
    
4. **사용자 그룹 설정 및 crictl 환경 구성**:
    - `ubuntu` 사용자를 docker 그룹에 추가하고, crictl이 containerd와 소통할 수 있도록 환경 설정 파일(`/etc/crictl.yaml`)을 작성합니다.
    - ubuntu - 사용자 이름에 따라 변경
    
    ```bash
    usermod -a -G docker ubuntu
    
    ```
    - containerd 운영시 docker명령어로 컨테이너 관리 불가합니다.
    - docker 명령을 대신해서 crictl 명령을 실행해야 합니다.
    - crictl 명령 사용을 위한 환경구성 파일 생성(/etc/crictl.yaml)
    - crictl 명령어 적용할 endpoint 설정. debug가 false일때 crictl명령 실행시 디버깅 메시지 출력되지 않음.
    - 추가 정보: https://github.com/kubernetes-sigs/cri-tools/blob/master/docs/crictl.md

    ```bash
    cat << END >> /etc/crictl.yaml
    runtime-endpoint: unix:///run/containerd/containerd.sock
    image-endpoint: unix:///run/containerd/containerd.sock
    timeout: 10
    debug: true
    END

    # containerd config file 구성
    mkdir -p /etc/containerd
    containerd config default | sudo tee /etc/containerd/config.toml
    ```
    
5. **구성파일의 systemdCgroup = true로 수정**:
    - 기본 설정 파일을 생성한 후, `SystemdCgroup` 옵션을 `true`로 수정하여 systemd 기반의 cgroup 관리 방식을 사용합니다.
    
    ```bash
    vi /etc/containerd/config.toml
    ```

    ```bash
    ...
    [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]
      ...
      [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc.options]
        SystemdCgroup = true   #139라인

    # crictl 명령어를 ubuntu 사용자가 실행할 수 있도록 uid, gid에 1000계정 할당
    # 17 라인
    [debug]
      gid = 1000
      uid = 1000

    [grpc]
      gid = 1000
      uid = 1000

    # 288 라인
    [ttrpc]
      gid = 1000
    uid = 1000
    ```
    
6. **서비스 재시작 및 상태 확인**:
    
    ```bash
    systemctl restart containerd
    systemctl status containerd
    ls -l /var/run/containerd/containerd.sock
    
    ```
    
    - 위 명령어를 통해 containerd 서비스가 정상적으로 실행되고 있는지, socket 파일의 권한이 올바른지 확인합니다.

## 3. kubeadm, kubelet, kubectl 설치 (모든 노드에서 수행)

Kubernetes 클러스터의 핵심 구성 요소들을 설치합니다.

### 설치 과정

1. **APT 저장소 준비**:
    - 필요한 패키지(apt-transport-https, ca-certificates, curl, gpg)를 설치하고, Google Cloud의 공개 서명 키를 추가합니다.
    
    ```bash
    sudo apt-get update
    sudo apt-get install -y apt-transport-https ca-certificates curl gpg
    curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.30/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

    echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.30/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list

    apt-get update
    
    ```
    
2. **특정 버전(예: 1.30.0) 설치 및 버전 고정**:
    - 설치 가능한 버전을 확인한 후 원하는 버전(1.30.0)을 설치하고, 향후 업데이트로 인한 변경을 막기 위해 패키지 버전을 고정합니다.
    
    ```bash
    sudo apt-cache madison kubeadm

    apt-get install -y kubelet=1.30.0-1.1 kubeadm=1.30.0-1.1 kubectl=1.30.0-1.1 --allow-change-held-packages

    apt-mark hold kubelet kubeadm kubectl


    kubelet --version
    
    ```

## 4. Kubernetes 클러스터 생성 및 구성

### 4.1 컨트롤 플레인 노드 초기화 (k8s-master)

- **클러스터 초기화**:
    - `kubeadm init` 명령어를 사용하여 컨트롤 플레인(마스터) 노드를 초기화합니다.
    - `-pod-network-cidr=192.168.0.0/16` 옵션은 선택한 Pod 네트워크 플러그인이 사용할 CIDR 블록을 지정합니다.
    - `-cri-socket` 옵션으로 containerd의 소켓 파일 경로를 지정합니다.
    
    ```bash
    kubeadm init --pod-network-cidr=192.168.0.0/16 --cri-socket unix:///var/run/containerd/containerd.sock
    
    ```
<details>
  <summary>CIDR `/16`의 의미</summary>
  `192.168.0.0/16` 은 **"192.168.0.0부터 시작해서, 서브넷 마스크가 16비트까지 네트워크 주소로 예약된 범위"** 라는 뜻입니다.

IPv4 주소는 32비트(4바이트) 로 이루어져 있으며, 다음처럼 표현할 수 있습니다.
```text
192.168.0.0  ->  11000000.10101000.00000000.00000000  (2진수)
```
여기서 `/16` 이라는 것은 **앞의 16비트(`11000000.10101000`)는 네트워크 주소**로 고정된다는 뜻입니다.

즉, 남은 **16비트(`00000000.00000000`)는 호스트 주소로 사용**할 수 있습니다.
남은 16비트(호스트 부분)는 2진수로 표현하면 **2의 16승(=65,536) 개의 조합이 가능**합니다.

즉, `192.168.0.0/16` 서브넷에서는 **192.168.0.0 ~ 192.168.255.255** 범위의 IP를 할당할 수 있으며,

이 범위 내에서 총 `65,536` 개의 IP를 사용할 수 있습니다.

하지만 일반적으로 **네트워크 주소(192.168.0.0)와 브로드캐스트 주소(192.168.255.255)는 사용할 수 없으므로, 실제 사용 가능한 IP 개수는 65,534 개**입니다.

---

### Kubernetes에서 CIDR을 설정하는 이유

Kubernetes 클러스터에서 **Pod들은 각자 고유한 IP를 갖고 통신**합니다.

이때, `--pod-network-cidr=192.168.0.0/16` 옵션을 주는 것은 **"모든 Pod가 사용할 수 있는 IP 범위"** 를 지정하는 것입니다.

즉,

- 클러스터 내부의 모든 Pod는 **192.168.0.0 ~ 192.168.255.255** 대역 내에서 IP를 갖게 됨
- **최대 65,534 개의 Pod에 대해 IP를 할당할 수 있음**
- 특정 CNI(Container Network Interface) 플러그인(Calico, Flannel 등)이 이 CIDR 범위를 사용하여 네트워크를 설정함

</details>

- **kubectl 설정**:
    - 컨트롤 플레인 초기화 후, 출력된 명령어를 참고하여 현재 사용자의 kubeconfig 파일을 생성합니다.
    
    ```bash
    mkdir -p $HOME/.kube
    cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
    chown $(id -u):$(id -g) $HOME/.kube/config
    
    ```
    
- **노드 조인 토큰 확보**:
    - 초기화 결과에 나온 `kubeadm join` 명령어(토큰 및 ca-cert hash 포함)를 기록해두어, 워커 노드가 클러스터에 참여할 때 사용합니다.
    ```bash
    kubeadm join 10.0.2.10:6443 --token n1mdg.....uv4 \
	  --discovery-token-ca-cert-hash sha256:6dd9...c605be2e38da 
    ```
    - 출력된 명령어에 따라 다름!
    ```bash
    # root 권한으로 worker node join을 위한 명령어. 별도 저장해둠.
    cat > token.join
    kubeadm join <Control-plane_IP>:6443 --token 2whvdj...qbbib \
            --cri-socket unix:///var/run/containerd/containerd.sock \
            --discovery-token-ca-cert-hash sha256:7125...78570b57
    <CTRL>+<d>
    ```

### 4.2 Pod 네트워크 애드온 설치

- **네트워크 플러그인**:
    - 클러스터 내 Pod들 간 통신을 위해 네트워크 애드온을 설치해야 합니다.
    
    ```bash
    kubectl apply -f https://github.com/weaveworks/weave/releases/download/v2.8.1/weave-daemonset-k8s.yaml
    
    ```
    
- **설치 확인**:
    - `watch kubectl get pod -A` 명령어를 통해 애드온이 다운로드되고 실행되었는지 모니터링합니다.
    - 이후 `kubectl get nodes`로 각 노드의 상태가 `Ready`인지 확인합니다.
    ```bash
    kubectl get nodes
    NAME          STATUS   ROLES           AGE     VERSION
    k8s-master    Ready    control-plane   4m56s   v1.30.0
    ```

### 4.3 워커 노드 클러스터 참여 (k8s-worker1, k8s-worker2)

- **워커 노드에서 클러스터 조인**:
    - 각 워커 노드에 SSH로 접속 후, root 권한(또는 sudo 권한)으로 토큰을 이용하여 클러스터에 참여시킵니다.
    - control plain node 에서 출력된 join 명령어 사이에 --cri-socket unix:///var/run/containerd/containerd.sock \ 를 추가하여 입력
    ```bash
    kubeadm join <Control-plane_IP>:6443 --token <토큰> \
      --cri-socket unix:///var/run/containerd/containerd.sock \
      --discovery-token-ca-cert-hash sha256:<해시값>
    
    ```
    
- **참여 확인**:
    - 클러스터에 조인되면 “Certificate signing request …” 등의 메시지가 출력되며, 컨트롤 플레인에서 `kubectl get nodes` 명령어를 실행해 모든 노드가 등록되고 `Ready` 상태인지 확인합니다.
    - `kubectl get nodes -o wide` 명령어를 사용하면 각 노드의 내부 IP, OS 이미지, 커널 버전, 컨테이너 런타임 정보 등도 확인할 수 있습니다.

## 5. 클러스터 기본 구성 및 추가 도구 설정

### kubectl 명령어 자동 완성

- **자동 완성 기능 설정**:
    - 클러스터 관리에 편리하도록, master 노드에서 kubectl 명령어 자동 완성을 설정합니다.
    
    ```bash
    apt-get install bash-completion -y


    source <(kubectl completion bash)
    echo "source <(kubectl completion bash)" >> ~/.bashrc
    
    ```
    

### etcd 설치 (control-plane에서 실행)

- **etcd 설치 및 확인**:
    - etcd는 Kubernetes의 백엔드 데이터 저장소로 사용됩니다.
    - 최신 etcd 버전을 GitHub API를 통해 확인하고 다운로드 후 압축을 풀어 `/usr/local/bin`으로 이동시킵니다.
    
    ```bash
    export RELEASE=$(curl -s https://api.github.com/repos/etcd-io/etcd/releases/latest | grep tag_name | cut -d '"' -f 4)
    wget https://github.com/etcd-io/etcd/releases/download/${RELEASE}/etcd-${RELEASE}-linux-amd64.tar.gz
    tar xf etcd-${RELEASE}-linux-amd64.tar.gz
    cd etcd-${RELEASE}-linux-amd64
    mv etcd etcdctl etcdutl /usr/local/bin
    etcd --version; cd
    
    ```
    
    - 명령어 실행 후 etcd 버전, Git SHA, Go 버전 등이 출력되며 정상적으로 설치되었는지 확인합니다.

### 일반 사용자(ubuntu)에게 kubectl 사용 권한 부여

- **사용자 환경 구성**:
    - ubuntu 계정이 클러스터 명령어를 실행할 수 있도록 kubeconfig 파일을 해당 사용자의 홈 디렉토리에 복사하고 소유권을 변경합니다.
    
    ```bash
    mkdir -p ~ubuntu/.kube
    cp -i /etc/kubernetes/admin.conf ~ubuntu/.kube/config
    chown ubuntu:ubuntu ~ubuntu/.kube/config
    chown ubuntu:ubuntu ~ubuntu/.kube -R
    
    ```
    
    - ubuntu 사용자로 로그인한 후 kubectl 자동 완성 및 상태 확인 명령어를 실행하여 모든 노드가 `Ready` 상태인지 확인합니다.
    ```bash
    source <(kubectl completion bash)
    echo "source <(kubectl completion bash)" >> ~/.bashrc
    kubectl get nodes
    NAME          STATUS   ROLES           AGE     VERSION
    k8s-master    Ready    control-plane   12m     v1.30.0
    k8s-worker1   Ready    <none>          6m27s   v1.30.0
    k8s-worker2   Ready    <none>          6m23s   v1.30.0
    ```

### 컨테이너 디버깅 도구: ctr & crictl

- **ctr**:
    - containerd와 직접 상호작용할 수 있는 CLI 도구입니다. 네임스페이스, 이미지, 컨테이너 상태 등을 확인할 수 있습니다.
    
    ```bash
    sudo ctr namespace ls
    sudo ctr -n k8s.io image ls
    sudo ctr -n k8s.io container list
    
    ```
    
- **crictl**:
    - CRI 호환 컨테이너 런타임과의 인터페이스를 제공하는 CLI 도구로, Docker 명령어와 유사한 사용법을 가집니다.
    
    ```bash
    sudo crictl images
    sudo crictl ps
    
    ```
    
    - 예를 들어 etcd 컨테이너의 로그를 확인할 때:
    
    ```bash
    sudo crictl ps | grep etcd
    sudo crictl logs <컨테이너_ID>
    
    ```
