# 서론 - 클라우드 & 클라우드 네이티브 개념

## 1. 클라우드 이해하기

### 1-1. 클라우드

- 인터넷을 통해서 언제 어디서든지 원하는 만큼 컴퓨팅 자원(컴퓨팅, 스토리지, 애플리케이션, 네트워크)을 손쉽게 사용할 수 있게 해주는 서비스
- 클라우드는 가상화 환경에서 탄생

### 1-2. 가상화

- 컴퓨터 리소스의 추상화
- 가상으로 애플리케이션, 서버, 스토리지, 네트워크와 같은 사물을 표현하기 위한 과정
- 소프트웨어 기술을 이용해 컴퓨터와 네트워크, 스토리지를 만들어내는 기술
- **가상화 기술의 장점**
  - 자원의 활용도 상승
    - 일반적인 상황에서, 서버가 물리적 하드웨어 리소스의 30%만 사용 → 리소스 낭비
    - 하이퍼바이저를 이용해 가상서버를 구성 → 서버별로 필요한 만큼만 리소스 할당

### 1-3. 클라우드를 사용했을 때의 이점

- 초기 선투자 비용 없음
- 규모의 경제로 인한 지속적인 가격 인하
- 탄력적인 운영 및 확장
  - 필요한 경우 몇 분 만에 확장 및 축소 가능
- 속도 및 민첩성 향상
- 비즈니스에만 집중 가능
- 글로벌 확장

## 2. Cloud Native

### 2-1. 클라우드 네이티브

- **CNCF: Cloud Native Computing Foundation**
  - 세계 최대의 개발자, 엔드 유저, 공급업체를 한자리에 모아 최대 규모의 오픈 소스 개발자 회의를 진행
  - 비영리 Linux Foundation 재단 산하 기관
- **CNCF가 말하는 클라우드 네이티브**
  - 클라우드 네이티브를 활용하면 조직은 퍼블릭, 프라이빗 및 하이브리드 클라우드와 같은 현대적, 역동적 환경에서 확장 가능한 애플리케이션 환경을 구축하고 실행할 수 있음

### 2-2. 클라우드 네이티브 사용 이유

| Category                   | Native APP | Web APP  | Cloud Native APP |
| -------------------------- | ---------- | -------- | ---------------- |
| 애플리케이션 개발방법론      | Waterfall  | Agile    | DevOps           |
| 애플리케이션 운영구조        | 모노놀릭      | 멀티티어     | 마이크로서비스       |
| 애플리케이션 운영 인프라      | 물리서버      | 가상서버(VM) | 컨테이너            |

> 생산성과 민첩성 증가

### 2-3. 컨테이너

- 애플리케이션을 운영체제로부터 분리시켜, 애플리케이션이 동작할 때 필요한 최소한의 환경을 제공

#### VM

- 호스트 OS 위에서 하이퍼바이저가 여러 개의 게스트 OS를 실행
- 각 VM은 독립적인 OS를 가지고 있어 부팅 속도가 느리고 무겁다

#### Docker

- 호스트 OS 위에서 Docker Engine이 여러 개의 컨테이너를 실행
- 컨테이너는 OS를 포함하지 않고, 애플리케이션과 라이브러리만 포함
- 같은 OS 커널을 공유하므로 가볍고 실행 속도가 빠름
- Docker는 **호스트 OS의 커널을 공유**하는 방식이므로, **커널이 다른 OS를 실행할 수 없음**
  - 즉, **Linux 기반 Docker는 Linux 커널을 공유**하고, **Windows 기반 Docker는 Windows 커널을 공유**

### 2-4. 마이크로 서비스 아키텍쳐

- 컨테이너 기반의 마이크로 서비스 아키텍처 구현
- 개발, 운영, 유지 보수 및 최신 트렌드 적용이 독립적으로 가능
- 병목 현상이 발생하는 서비스만 스케일 아웃
- 독립적으로 서비스를 운영하기 때문에 새로운 트렌드에 따른 기능 추가가 용이

### 2-5. CICD, DevOps, GitOps

- **CI/CD (Continuous Integration/Continuous Delivery or Deployment)**
  - 애플리케이션 개발 단계를 자동화하여 더 짧은 주기로 고객에게 제공하는 방법론
  - **지속적 통합 (Continuous Integration, CI)**
    - 애플리케이션 코드의 새로운 변경 사항을 정기적으로 빌드 및 테스트 후 공유 리포지토리에 병합
    - 다수의 개발자가 작업할 때 발생하는 소스 코드 충돌 문제 해결
  - **지속적 제공 (Continuous Delivery, CD)**
    - 변경 사항을 버그 테스트 후 리포지토리에 자동 업로드
    - 코드 변경 사항 병합, 프로덕션 빌드 제공 단계에서 테스트 자동화 및 코드 릴리스 자동화를 포함
  - **지속적 배포 (Continuous Deployment, CD)**
    - 리포지토리에서 고객이 사용 가능한 프로덕션 환경까지 자동으로 릴리스
    - 개발자가 변경 사항을 작성한 후 몇 분 내에 클라우드 애플리케이션이 자동으로 실행됨
- **CI/CD와 DevOps 관계**
  - DevOps는 개발(Development)와 운영(Operation)을 결합해 탄생한 개발 방법론
  - 시스템 개발자와 IT 운영 전문가 사이의 소통, 협업, 통합 및 자동화를 강조
  - DevOps에서의 CI/CD는 기술 및 프로세스적인 부분을 의미
  - **DevOps의 요소**
    - 지속적 통합
    - 지속적 전달
    - 마이크로 서비스
    - 코드형 인프라
    - 모니터링 및 로깅
    - 커뮤니케이션 및 통합
- **GitOps란?**
  - 애플리케이션 코드, 인프라, 네트워킹, CI/CD 파이프라인 등 전체 애플리케이션 생태계 구성요소를 모두 Git에 저장하여 관리하는 방식
