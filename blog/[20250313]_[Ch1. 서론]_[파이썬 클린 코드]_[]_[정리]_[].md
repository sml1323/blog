# Chapter 1. 서론
<details>
  <summary>`attribute` vs. `property`의 차이</summary>

| 개념 | 설명 | 예시 |
| --- | --- | --- |
| **Attribute (일반 속성)** | 클래스의 **변수(필드)**로, 값이 직접 저장됨. | `obj.name = "Alice"` |
| **Property (프로퍼티)** | 속성처럼 보이지만, **getter, setter 등을 활용한 메서드 기반 속성** | `obj.age = 30 # 내부적으로 setter 메서드 실행` |

### Getter, Setter 사용 예제

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self._age = age  # 진짜 값은 _age에 저장 (보호를 위해 _ 사용)

    @property
    def age(self):
        """getter 역할: 값을 가져올 때 호출됨"""
        print("getter 호출됨")
        return self._age

    @age.setter
    def age(self, value):
        """setter 역할: 값을 변경할 때 호출됨"""
        print("setter 호출됨")
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person("Alice", 30)

print(p.age)  # getter 호출됨 → 30
p.age = 35    # setter 호출됨
print(p.age)  # getter 호출됨 → 35
```

---

## ✅ `@property`를 사용하는 4가지 주요 장점

### 1️⃣ 캡슐화(Encapsulation) - 내부 구현을 숨길 수 있음

일반 속성(`self.age`)을 직접 사용하면, 속성의 내부 구조가 변경될 때 코드를 수정해야 할 수도 있음.

#### ❌ 일반 속성을 사용하면?

```python
class Person:
    def __init__(self, age):
        self.age = age  # 그냥 속성

p = Person(30)
print(p.age)  # 30
p.age = -5  # 잘못된 값이 들어감! (문제 발생)
```

위 코드에서는 `p.age = -5`처럼 **잘못된 값**을 막을 방법이 없음.

---

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, age):
        self._age = age  # 실제 값은 _age에 저장

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person(30)
p.age = -5  # ❌ ValueError 발생! (잘못된 값 차단)
```

✔️ **외부에서 직접 `self._age`에 접근하지 못하게 하고, setter를 통해 제어하는 방식!**

---

### 2️⃣ 인터페이스 유지 - 내부 구현을 바꿔도 외부 코드는 그대로 유지됨

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, birth_year):
        self._birth_year = birth_year  # 출생 연도를 저장

    @property
    def age(self):
        """현재 연도(2024)에서 출생 연도를 빼서 나이 계산"""
        return 2024 - self._birth_year

p = Person(1994)
print(p.age)  # 30  (출생 연도 기반 계산)
```

✔️ **속성 이름(`age`)을 그대로 유지하면서 내부 구현을 바꿀 수 있음!**

---

### 3️⃣ 동적 계산 가능 (Lazy Evaluation)

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        """넓이를 매번 계산하여 반환"""
        return self.width * self.height

r = Rectangle(5, 10)
print(r.area)  # 50  (속성처럼 보이지만 실제로는 메서드 실행)
```

✔️ **데이터를 저장하지 않고, 필요할 때마다 계산할 때 유용!**

---

### 4️⃣ 읽기 전용 속성 만들기 가능 (Setter 없이 Getter만 사용)

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def diameter(self):
        """지름은 반지름의 2배이며, 변경할 수 없음"""
        return self._radius * 2

c = Circle(10)
print(c.diameter)  # 20
c.diameter = 30  # ❌ AttributeError: can't set attribute (setter가 없으므로 수정 불가)
```

✔️ **읽기 전용 속성이 필요할 때 getter만 사용하면 됨.**

## 01. 클린 코드

- 클린코드는 다른 엔지니어가 코드를 읽고 유지 관리할 수 있는지 여부에 달려있다.
- 유지보수성 향상, 지속적인 배포
- 기술부채: 개발팀이 제 시간에 어떤 것을 제공할 수 없어서 코드를 수정하고 리팩토링하기 위해 멈춘다는 것
- agile ↔ rigid
- 좋은 코드 레이아웃을 위한 가장 필요한 특성은 일관성이다. → 구조화 → 가독성 상승
- 말의 위치가 무작위일 경우 체스 마스터들도 일반인과 다름 없었지만, 논리적 순서를 따랏을 경우 체스 마스터들이 압도했다.

## 02. 문서화 - Documentation

### 코드 주석 - Code Comments

- 가능한 적은 주석을 사용하는것을 목표로 해야한다. 좋은 코드는 코드 자체가 문서화 되어있기 때문이다.
- 즉 주석을 사용하는 것은 코드를 올바르게 작성하지 않았다는 징후이다.
- 문서화는 코드 설계 방식이나 아키텍쳐를 설명하는 것을 의미하며 이는 긍정적인 효과를 가져온다.

### Docstring

- Docstring은 소스코드에 포함된 문서(Documention) 라고 할 수 있다. → 이유가 아니라 설명이다.
- Docstring은 코멘트가 아니라 문서이다.
- Docstring을 추가하려고 노력하는 것은 좋은 습관이다.
- 파이썬은 동적인 데이터타입을 갖기 때문에, 파이썬 함수의 파라미터 값으로 어떤 데이터 타입도 취할 수 있다. 이런 경우, docstring을 추가하는것은 도움이 된다.

# Ch2. Pythonic 코드

### 자체 시퀀스 생성

매직 메서드: `__getitem__`

- `list`\[1:3], `list`\[::], `list`\[-1], `list`\[1:7:2] 와 같은 리스트 슬라이싱은 `slice` 함수에 파라미터를 전달하는 것과 같다. `interval = slice(1,7,2)`, `my_number`\[slice] 와 같이 직접 호출 가능하다.
- 위 기능은 매직 메서드 덕분에 동작한다.
- 매직 메서드

  이 코드를 이해하려면 `__getitem__` 매직 메서드와 `slice` 객체가 어떻게 동작하는지 알아야 한다.

  ---

  ## 1. `__getitem__` 매직 메서드란?

  `__getitem__`은 객체에서 `[]`(대괄호)로 값을 가져올 때 호출되는 매직 메서드.

  예를 들어, 파이썬의 리스트는 내부적으로 `__getitem__`을 구현하고 있어서 이런 코드가 가능하다: 

  \`\`\`python
  my_list = [10, 20, 30, 40, 50]
  print(my_list\[2])  # 30 (== my_list.__getitem__(2))
  \`\`\`

  즉, `my_list`\[2]는 실제로 `my_list.__getitem__(2)`를 호출하는 것과 같음.

  ---

  ## 2. 직접 만든 클래스에서 `__getitem__` 구현하기

  이제 `Items` 클래스를 보자. 이 클래스는 `__getitem__`을 직접 구현:

  \`\`\`python
  class Items:
      def __init__(self, *values):
          self._values = list(values)  # 내부 리스트 저장

      def __len__(self):
          return len(self._values)  # 길이 반환

      def __getitem__(self, item):
          return self._values.__getitem__(item)  # 내부 리스트의 __getitem__ 호출
  \`\`\`

  이제 이 클래스를 사용:

  \`\`\`python
  nums = Items(10, 20, 30, 40, 50)

  print(nums\[2])  # 30  (== nums.__getitem__(2))
  \`\`\`

  위 코드에서 `nums`\[2]를 호출하면 내부적으로 `self._values`\[2]가 실행돼. 결국 `self._values`가 리스트이므로, 리스트의 `__getitem__`이 실행되는 거지.

  ---

  ## 3. 리스트 슬라이싱과 `slice` 객체

  리스트에서 슬라이싱을 하면 사실 `slice` 객체를 생성해서 `__getitem__`에 전달하는 방식.

  예를 들어:

  \`\`\`python
  my_list = [10, 20, 30, 40, 50]
  print(my_list\[1:4])  # [20, 30, 40]
  \`\`\`

  이때 `my_list.__getitem__(slice(1, 4))`이 호출.

  즉, `my_list`\[1:4]는 `slice(1, 4)`라는 객체를 만들어서 `__getitem__`에 넘기는 것과 같음.

  이걸 `Items` 클래스에서도 확인:

  \`\`\`python
  nums = Items(10, 20, 30, 40, 50)
  print(nums\[1:4])  # [20, 30, 40]
  \`\`\`

  이때 내부적으로 `nums.__getitem__(slice(1, 4))`이 실행되고, 다시 내부 리스트의 `__getitem__`을 호출해서 `\[20, 30, 40]`을 반환.

  ---

  ## 4. `slice` 객체 직접 사용해보기

  슬라이싱은 결국 `slice` 객체를 만든다는 걸 확인해볼 수 있음.

  \`\`\`python
  interval = slice(1, 4)
  print(my_list\[interval])  # [20, 30, 40]
  \`\`\`

  즉, `my_list`\[1:4]는 `slice(1, 4)`를 생성해서 `__getitem__`에 넘기는 것과 같음.

  ---

  ## 5. Items 클래스에서 `__getitem__`의 역할

  이제 `Items` 클래스에서 `__getitem__`이 하는 일을 정리.

  - `nums`\[2] → `self._values`\[2] 호출 → `30` 반환
  - `nums`\[1:4] → `self._values`\[slice(1, 4)] 호출 → `\[20, 30, 40]` 반환

  즉, `__getitem__`이 리스트의 인덱싱/슬라이싱 기능을 그대로 전달하는 역할을 함.

  ---

  ## ✅ 정리

  - `__getitem__`은 객체에서 `[]` 연산자를 처리하는 매직 메서드.
  - 슬라이싱(`obj`\[start:end:step])을 하면 `slice(start, end, step)` 객체가 `__getitem__`에 전달.
  - `Items` 클래스는 내부 리스트 `_values`의 `__getitem__`을 그대로 호출해서 리스트처럼 동작할 수 있게 함.

## 컨텍스트 관리자(context manager)

- 사전 조건과 사후 조건이 있는 코드, 즉 작업 전후에 실행하는 상황에서 사용하는 도구

\`\`\`python
fd = open(filename):
	try:
		process_file(fd)
	finally:
		fd.close()
\`\`\`

> 위와 같은 기능을 Pythonic한 코드로 짧게 구현할 수 있다.

\`\`\`python
with open(filename) as fd:
	process_file(fd)
\`\`\`

> with 문은 컨텍스트 관리자로 진입하게 한다. 이 경우 open 함수는 컨텍스트 관리자 프로토콜을 구현하여 예외가 발생한 경우에도 블록이 완료되면 파일이 자동으로 닫힌다.
>
- 컨텍스트 관리자는 `__enter__` 와 `__exit__` 두 개의 매직 메서드로 구성된다.

## 컴프리헨션 - Comprehension 과 할당 표현식

- 단일 명령어로 데이터 구조를 생성하려면 컴프리헨션을 사용하는 것이 좋다.

\`\`\`python
numbers = []
for i in range(10):
	numbers.append(run_calculation(i))
\`\`\`

> 위 예제는 다음과 같이 바로 리스트로 만들 수 있다.

\`\`\`python
numbers = [run_calculation(i) for i in range(10)]
\`\`\`

- 위같이 작성된 코드는 일반적으로 append를 반복적으로 호출하는 것보다 나은 성능을 보인다.

def collect_account_ids_from_arns(arns):

## Property, Attribute 와 객체 메서드의 다른 타입들

- public, private, protected 와 같은 접근 제어자를 가지는 다른 언어들과는 다르게 파이썬 객체의 모든 속성과 함수는 public이다. 즉, 호출자가 객체의 속성을 호출하지 못하도록 할 방법이 없다.
- 파이썬에서는 변수명 지정과 관련해서 몇가지 네이밍 컨벤션이 있다.
    - private: 밑줄로 시작하는 속성. → `_age`, `_year` …
    - protected: 이중 밑줄로 시작하는 속성. → `__age`, `__year` ..

### 파이썬에서의 밑줄

- 밑줄 두개를 사용하면 파이썬은 다른 이름을 만든다. 이름 맹글링(name mangling) 이라는 것으로 이중 밑줄을 사용한 변수의 이름을 “`_<class_name>__<attribute-name>`” 형태로 변경하는 것이다.
- 따라서 Connect 클래스의 `__timeout` 속성은 다음과 같이 접근할 수 있다.

> `conn = Connect()`, `conn._Connect__timeout`

- 이중 밑줄은 Pythonic 한 방식이 아니다.

### 프로퍼티

- 좌표값을 처리하는 지리 시스템에서, 위도와 경도는 특정 범위 내에서만 의미가 있다. 이런 경우 프로퍼티를 사용할 수 있다. 값을 사용할 때는 항상 허용 가능한 범위 내에 있는지 확인해야 한다.

\`\`\`python
class Coordinate:
	def __init__(self, lat: float, long: float) -> None:
		self._latitude = self._longtitude = None
		self._latitude = lat
		self._longitude = long

	@property
	def latitude(self) -> float:
		return self._latitude
	@latitude.setter
	def latitude(self, lat_value: float) -> None:
		if not -90 <= lat_value <= 90:
			raise ValueError(f"유효하지 않은 위도 값: {lat_value}")
		self._latitude = lat_value
	@property
	def longitude(self) -> float:
		return self._longitude

	@longitude.setter
	def longitude(self, long_value: float) -> None:
		if not -180 <= long_value <= 180:
			raise ValueError(f"유효하지 않은 경도 값: {long_value}")
		self._longitude = long_value
\`\`\`

- 프로퍼티는 명령-쿼리 분리 원칙(command and query separation) 을 따르기 위한 좋은 방법이다.

> 명령-쿼리 분리 원칙이란 객체의 메서드가 무언가의 상태를 변경하는 커맨드이거나 무언가의 값을 반환하는 쿼리이거나 둘 중에 하나만 수행해야지 둘 다 동시에 수행하면 안된다는 것이다.
>
- 메서드는 한가지만 수행해야 한다. 작업을 처리한 다음 상태를 확인하려면 메서드를 분리해야 한다.

### 보다 간결한 구문으로 클래스 만들기

파이썬에는 객체의 값을 초기화 하는 일반적인 보일러플레이트(boilerplate code: 모든 프로젝트에서 공통적으로 반복해서 사용되는 코드) 코드가 있다.

\`\`\`python
def __init__(self, x, y, ...):
	self.x = x
	self.y = y
\`\`\`

dataclasses 모듈을 사용하여 위 코드를 훨씬 단순화 할 수 있다.

- `@dataclass` 모듈을 사용하면 `__init__` 메서드를 자동으로 생성하므로 또다시 구현할 필요가 없다.
- dataclasses의 `field` 객체는 해당 속성에 특별한 특징이 있음을 표시한다.
    - 속성 중 하나가 `list` 처럼 mutable 데이터 타입일 경우, `__init__`에서 비어 있는 리스트를 할당할 수 없고 대신에 `None`으로 초기화한 다음에 인스턴스마다 적절한 값으로 다시 초기화를 해야한다.

    > 필드의 기본 값이 인스턴스마다 공유되는 값이기 때문에 변경된 초기값을 다음 인스턴스에서 잘못 사용할 수 있기 때문이다. mylist = [] 처럼 할당할 경우 다음 에러가 발생한다. `ValueError: mutable default <class 'list'> for field friends is not allowed: use default_factory)`
    >
    - field 객체를 사용하면 `default_factory` 파라미터에 `list` 객체를 전달하여 초기값을 지정할 수 있다.

\`\`\`python
from dataclasses import dataclass, field
from typing import List

@dataclass
class DataClassCard:
    rank: str
    suit: str
    hard: List\[int] = field(default_factory=list)
\`\`\`

**`R-Trie` 자료구조**

R: radix
일부 기본 요소(base R) 에 대한 인덱싱된 트리

> radix: 주어진 데이터를 구성하는 기본 요소, 문자열을 검색하는 경우 알파벳이 기본요소
>
- 문자열에 대한 빠른 검색을 위해 사용

이 자료구조는 현재의 문자를 나타내는 value와 다음에 나올 문자를 나타내는 next_ 배열을 가지고 있다. a로 시작하는 단어 집합을 표현하려는 경우 value에 a가 저장되고 next_에는 이어지는 문자의 종류별로 R-Trie 노드에 대한 참조가 저장된다.

\`\`\`python
from typing import List
from dataclasses import dataclass, field

R = 26

@dataclass
class RTrieNode:
    size = R
    value: int
    next_: List["RTrieNode"] = field(default_factory=lambda: [None] * R)

    def __post_init__(self):
        if len(self.next_) != self.size:
            raise ValueError(f"리스트(next_)의 길이가 유효하지 않음")
\`\`\`

- `next_: List["RTrieNode"] = []` 이렇게 `next_`를 초기화 하면 모든 인스턴스가 동일한 리스트를 참조한다. 기본값으로 [] 같은 `mutable` 객체를 사용하면 그 객체가 모든 인스턴스에서 공유된다.

> `default_factory`에는 함수 객체가 들어가야 한다. 따라서 `default_factory=[None]*R` 은 에러가 나기 때문에, `lambda: [None] * R`을 사용하거나, `list` 같이 함수를 적어야 한다.

### 이터러블 객체

- list, tuple, set, dict 와 같이 for 루프를 통해 반복적으로 값을 가져올 수 있는 객체
- 엄밀히 말하면 `__iter__` 매직 메서드를 구현한 객체, 이터레이터는 `__next__` 매직 메서드를 구현한 객체

### 이터러블 객체 만들기

- 일정 시간의 날짜를 하루 간격으로 반복하는 객체의 코드

\`\`\`python
from datetime import timedelta, datetime

class DateRangeIterable:
    """ 자체 이터레이터 메서드를 가지고 있는 이터러블 """
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date
        self._present_day = start_date

    def __iter__(self):
        return self

    def __next__(self):
        if self._present_day >= self.end_date:
            raise StopIteration
        today = self._present_day
        self._present_day += timedelta(days=1)
        return today

for day in DateRangeIterable(datetime(2019, 1, 1), datetime(2019, 1, 5)):
    print(day)
# 2019-01-01 00:00:00
# 2019-01-02 00:00:00
# 2019-01-03 00:00:00
# 2019-01-04 00:00:00
\`\`\`

- 이 예제는 잘 동작하나 한번 실행하면 끝의 날짜에 도달한 상태이므로 계속 호출하면 `StopIteration` 예외가 발생한다. 두 개 이상의 for루프에서 이 값을 사용하면 첫번째 루프만 작동하고 두 번째 루프는 작동하지 않게 된다.
- 이터 매직 메서드는 이터레이터를 반환하고 이 이터레이터를 사용해 반복한다. 이터 매직 메서드에 제너레이터를 사용할 수도 있다.

\`\`\`python
from datetime import timedelta, datetime

class DateRangeIterable:
    """ 제너레이터를 사용한 이터러블 """
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date

    def __iter__(self):  # 제너레이터 함수 사용
        present_day = self.start_date
        while present_day < self.end_date:
            yield present_day  # 값을 하나씩 반환

### 시퀀스 만들기

- `__len__` 과 `__getitem__` 을 구현하고 첫 번째 인덱스 0 부터 시작하여 포함된 요소를 한 번에 하나씩 차례로 가져올 수 있어야 한다.
- 이전 코드처럼 이터러블을 사용하면 메모리는 적게 사용하지만 n 번째 요소를 얻기 위한 시간복잡도는 $O(n)$ 이다. 하지만 시퀀스로 구현하면 메모리 사용량은 증가하나 인덱싱의 시간복잡도는 $O(1)$로 상수에 가능하다.

\`\`\`python
from datetime import timedelta, datetime

class DateRangeSequence:
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date
        self._range = self._create_range()

    def _create_range(self):
        days = []
        current_day = self.start_date
        while current_day < self.end_date:
            days.append(current_day)
            current_day += timedelta(days=1)
        return days

    def __getitem__(self, day_no):
        return self._range\[day_no]

    def __len__(self):
        return len(self._range)
s1 = DateRangeSequence(datetime(2021, 1, 1), datetime(2021, 1, 5))
for days in s1:
    print(days)

print(s1\[3])
# 2021-01-01 00:00:00
# 2021-01-02 00:00:00
# 2021-01-03 00:00:00
# 2021-01-04 00:00:00
# 2021-01-04 00:00:00

### 객체의 동적인 속성

- `__getattr__` 매직 매서드를 사용하면 객체가 속성에 접근하는 방법을 제어할 수 있다.
- `<myobject>.<myattribute>` 형태로 객체의 속성에 접근하려고 하면 파이썬은 객체 인스턴스의 attribute 정보를 가지고 있는 `__dict__`사전에서 `<myattribute>`가 있는지 검색한다.
    - 존재할 경우 `__getattribute__` 메서드 호출
    - 존재하지 않을 경우 조회하려는 `myattribute`의 이름을 파라미터로 하여 `__getattr__` 메서드를 호출한다.
    - 따라서 `__getattr__` 메서드를 활용하면 존재하지 않는 속성에 대한 행동 제어가 가능하다.

    > `__dict__` 변수는 인스턴스 마다 별도로 생성된다.

\`\`\`python
class DynamicAttributes:
    def __init__(self, attribute):
        self.attribute = attribute
    def __getattr__(self, attr):
        if attr.startswith("fallback_"):
            name = attr.replace("fallback_", "")
            return f"[fallback resolved] {name}"
        raise AttributeError(f"{self.__class__.__name__}에는 {attr} 속성이 없습니다.")

dyn = DynamicAttributes("value")
print(dyn.attribute)
print(dyn.fallback_test)

dyn.__dict__["fallback_test"] = "new value"

print(getattr(dyn, "fallback_test"))
print(getattr(dyn, "fallback_test2"))
\`\`\`

1. `dyn = DynamicAttributes("value")`, `dyn.attribute`: 일반적인 속성 저장 방식
2. `__getattr__`의 동작 방식
    1. **속성이 존재하면** (`self.__dict__`에 있으면) 정상적으로 반환 → `__getattr__`은 호출되지 않음
    2. **속성이 없으면** `__getattr__`이 실행됨
    3. 만약 속성이 `"fallback_"`으로 시작하면 `"fallback_"`을 제거하고 `"fallback resolved"` 메시지를 반환
    4. 그렇지 않으면 `AttributeError` 발생
3. `dyn.fallback_test`가 호출될 때 일어나는 일
    1. `dyn` 객체에 `fallback_test` 속성이 있는지 확인 (`__dict__` 체크)
    2. 존재하지 않음 → `__getattr__` 호출됨
    3. `"fallback_"`으로 시작하므로 `"test"`라는 이름을 추출
    4. `"[fallback resolved] test"`를 반환
4. `__dict__`를 직접 수정하는 부분
    1. `__dict__`는 객체의 속성을 저장하는 **내부 딕셔너리**
    2. 여기서 `dyn.fallback_test = "new value"`를 직접 넣은 것과 같음
    3. 즉, 이제 `dyn.fallback_test`가 `__dict__`에 직접 저장되었으므로 **`__getattr__`이 실행되지 않음**
5. `getattr(dyn, "fallback_test")`
    - new value
6. `getattr(dyn, "fallback_test2")`
    - \[fallback resolved] test2

> `__getattr__`처럼 동적으로 변하는 속성에 대한 메서드를 작성하려고 하는 경우, 존재하지 않는 속성에 접근하려고 하면 AttributeError를 발생시켜야 한다.

### 호출형 객체(Callable)

- 객체를 일반 함수처럼 호출하면 `__call__` 매직 메서드가 호출된다. 객체 호출시 사용되는 파라미터들은 이 메서드에 그대로 전달된다.

> 파이썬은 `object(*args, **kwargs)`같은 구문으로 생성한 객체를 `object.__call__(*args, **kwargs)`형태로 변환한다.

- 다음 코드는 동일한 파라미터 값으로 몇번이나 호출되었는지를 카운트 하기 위해 `__call__`메서드를 사용하는 예제이다.

\`\`\`python
from collections import defaultdict

class CallCount:
    def __init__(self):
        self._counts = defaultdict(int)

    def __call__(self, argument):
        self._counts\[argument] += 1
        return self._counts\[argument]

cc = CallCount()
cc(1) # -> 1
cc(1) # -> 2
cc(2) # -> 1
\`\`\`

## 파이썬에서 유의할 점

### 변경가능한(mutable) 파라미터의 기본 값

- 변경 가능한 객체를 함수의 기본 인자로 사용하면 안된다.

\`\`\`python
def wrong_user_display(user_metadata: dict = {"name":"John", "age":30}):
    name = user_metadata.pop("name")
    age = user_metadata.pop("age")
    return f"{name} is {age} years old"
\`\`\`

- 위와 같은 코드는 호출 시 처음에만 정상작동한다.

> 파이썬 인터프리터는 함수의 시그니처에서 사전을 기본값으로 하는 코드를 발견하면 해당 파라미터에 사전을 생성하여 할당한다. 사전은 한번만 생성되며 프로그램이 종료될 때 까지 모든 객체의 인스턴스는 같은 기본값을 참조한다.

- 다음과 같이 None으로 초기값을 설정하고 함수 본문에서 기본값을 할당하면 된다.

\`\`\`python
def wrong_user_display(user_metadata: dict = None):
    user_metadata = user_metadata or  {"name":"John", "age":30}
    name = user_metadata.pop("name")
    age = user_metadata.pop("age")
    return f"{name} is {age} years old"
\`\`\`

## 비동기 코드(asynchronous code)에 대한 간략한 소개

- 비동기 프로그래밍의 기본 아이디어는 중지(suspend) 가능한 코드가 있다면 그동안 다른 코드를 실행하자는 것이다. 일반적으로 I/O 작업시 사용된다.
- 동기적으로 코드를 호출하여 해당 기능이 종료될 때 까지 기다리는 대신 이벤트 루프에서 우리의 코드를 호출하도록 변경한다. 이벤트 루프는 코루틴들을 스케줄링하는 역할을 하며 동일한 스레드에서 실행한다.
1. 일련의 코루틴을 만들고 이벤트루프에 추가한다.
2. 이벤트 루프가 시작되면 가지고 있는 코루틴 중에서 하나를 선택하여 실행한다.
3. 코루틴 중 하나가 I/O 작업을 실행하면 이벤트 루프에서 권한을 넘긴다.
4. 이벤트 루프는 I/O 작업이 진행되는 동안 다른 코루틴을 실행한다.
5. I/O 작업이 종료되면 중지된 코루틴은 마지막 지점에서 다시 해당 코루틴을 시작한다.

> 이름 앞에 `async def`가 추가되고, 코루틴 안에서 다른 코루틴을 호출하려면 `await` 키워드를 사용한다. await를 사용하면 이벤트 루프가 제어권을 되찾아 온다.

# Ch3. 좋은 코드의 일반적인 특징

## 계약에 의한 디자인

- 컴포넌트는 기능을 숨겨 캡슐화 하고 함수를 사용할 클라이언트에게는 **애플리케이션 프로그래밍 인터페이스(Application Programming Interface - API)**를 노출해야 한다.
- **계약에 의한 디자인(Design by Contract)**이란 관계자가 기대하는 바를 암묵적으로 코드에 삽입하는 대신 양측이 동의하는 계약을 먼저 한 다음, 계약을 어겼을 경우에는 명시적으로 왜 계속할 수 없는지 예외를 발생시키라는 것이다.
    - 사전조건(Precondition): 코드가 실행되기 전에 체크해야 될 것들
    - 사후조건(Postcondition): 함수 반환값의 유효성 검사
    - 불변식(Invariant): 함수가 실행되는 동안에 일정하게 유지되는 것으로 함수의 로직에 문제가 없는지 확인하기 위한 것
    - 부작용(side-effect)

## 방어적 프로그래밍

> 계약에서 예외를 발생시키고 실패하게 되는 모든 조건을 기술하는 대신 객체, 함수 또는 메서드와 같은 모든 부분을 유효하지 않은 것으로부터 스스로 보호할 수 있게 하는 것이다.

### 에러 핸들링

- 주요 목적은 예상되는 에러에 대해서 실행을 계속할 수 있을지 아니면 극복할 수 없는 오류여서 프로그램을 중단할지를 결정하는 것
    - 값 대체(value substitution)
        - 잘못된 결과를 정합성을 깨지 않는 다른 값으로 대체
    - 에러 로깅
    - 에러 처리

### 예외 처리

- 예외적인 상황을 명확히 알려주고 원래의 비즈니스 로직에 따라 흐름을 유지

**올바른 수준의 추상화 단계에서의 예외 처리**

- 예외는 오직 한 가지 일을 하는 함수의 한 부분이여야 한다.함수가 처리하는 예외는 함수가 캡슐화하고 있는 로직에 대한 것이여야 한다.

\`\`\`python
import time
import logging
from typing import Protocol

logger = logging.getLogger(__name__)

class Connector(Protocol):
    def connect(self):
        ...

class Event(Protocol):
    def decode(self):
        ...

class DataTransport:
    """다양한 수준의 예외를 처리하는 예 """
    _RETRY_BACKOFF: int = 5
    _RETRY_TIMES: int = 3

    def __init__(self, connector: Connector) -> None:
        self._connector = connector
        self.connection = None
    def deliver_envet(self, event: Event):
        try:
            self.connect()
            data = event.decode()
            self.send(data)
        except ConnectionError as e:
            logger.info("커넥션 오류 발견: %s", e)
            raise
        except ValueError as e:
            logger.error("%r 이벤트에 잘못된 데이터 포함: $s", event, e)
            raise

    def connect(self):
        for _ in range(self._RETRY_TIMES):
            try:
                self.connection = self._connector.connect()
            except ConnectionError as e:
                logger.info("%s: 새로운 커넥션 시도 %is", e, self._RETRY_BACKOFF)
                time.sleep(self._RETRY_BACKOFF)
            else:
                return self.connection
        raise ConnectionError(f"{self._RETRY_TIMES} 번의 재시도 모두 실패")
    def send(self, data: bytes):
        return self.connection.send(data)
\`\`\`

- 핵심은 적절한 추상화 수준에서 예외를 처리하고 재시도를 통해 연결 오류를 복구하는것이다

### 🔹 설명

## 1. `DataTransport` 클래스 개요

이 클래스는 데이터 전송을 담당하는 역할을 합니다. 핵심 기능은:

- **서버에 연결**
- **이벤트 데이터를 디코딩하여 전송**
- **연결이 실패하면 재시도**
- **예외가 발생하면 적절한 로깅을 수행**

### 🔹 주요 속성

\`\`\`python
    _RETRY_BACKOFF: int = 5
    _RETRY_TIMES: int = 3
\`\`\`

- `_RETRY_BACKOFF`: 연결이 실패하면 몇 초 동안 기다릴지 (5초)
- `_RETRY_TIMES`: 연결을 몇 번 재시도할지 (3번)

---

## 2. `__init__` 생성자

\`\`\`python
    def __init__(self, connector: Connector) -> None:
        self._connector = connector
        self.connection = None
\`\`\`

- `self._connector`: `Connector` 객체를 받아서 연결을 시도할 때 사용
- `self.connection`: 실제 연결된 상태를 저장

---

## 3. `deliver_event()` - 데이터 전송 메서드

\`\`\`python
    def deliver_envet(self, event: Event):
        try:
            self.connect()  # 서버에 연결 시도
            data = event.decode()  # 이벤트 데이터를 디코딩
            self.send(data)  # 데이터를 전송
        except ConnectionError as e:
            logger.info("커넥션 오류 발견: %s", e)
            raise  # 예외를 다시 던짐 (상위 코드에서 처리 가능하도록)
        except ValueError as e:
            logger.error("%r 이벤트에 잘못된 데이터 포함: %s", event, e)
            raise  # 데이터가 잘못되었으면 예외 발생
\`\`\`

### 🔹 동작 방식

1. `connect()`를 호출하여 서버 연결을 시도
2. `event.decode()`를 통해 이벤트 데이터를 디코딩 (문제 발생 가능)
3. `send(data)`로 데이터를 전송
4. 예외 발생 시:
    - **`ConnectionError`** → 로깅 후 예외 다시 발생 (상위 코드에서 처리)
    - **`ValueError`** → 잘못된 데이터가 포함된 경우 로깅 후 예외 발생

### 🔥 `raise`의 의미?

- `raise`를 사용하여 예외를 다시 던지면, 이 함수가 호출된 상위 코드에서 예외를 감지하고 적절히 처리할 수 있습니다.

---

## 4. `connect()` - 연결 시도 및 재시도 로직

\`\`\`python
    def connect(self):
        for _ in range(self._RETRY_TIMES):  # 최대 3번 재시도
            try:
                self.connection = self._connector.connect()  # 연결 시도
            except ConnectionError as e:
                logger.info("%s: 새로운 커넥션 시도 %is", e, self._RETRY_BACKOFF)
                time.sleep(self._RETRY_BACKOFF)  # 5초 기다렸다가 재시도
            else:
                return self.connection  # 연결 성공하면 반환
        raise ConnectionError(f"{self._RETRY_TIMES} 번의 재시도 모두 실패")
\`\`\`

### 🔹 동작 방식

1. 최대 `_RETRY_TIMES`(3번) 동안 연결을 시도
2. `connect()`가 실패하면 **로그를 남기고 5초간 대기 후 다시 시도**
3. 3번 시도 후에도 연결이 안 되면 `ConnectionError`를 발생시킴

---

## 5. `send()` - 데이터 전송

\`\`\`python
    def send(self, data: bytes):
        return self.connection.send(data)
\`\`\`

- 연결된 `self.connection`을 사용하여 데이터를 전송
- 이 함수 자체는 예외 처리를 하지 않음 → **예외는 `deliver_event()`에서 처리**

---

## 6. **예외 처리의 추상화 수준**

이 코드의 핵심은 **각 메서드가 적절한 수준에서 예외를 처리하고 있는가**입니다.

| 메서드 | 예외 처리 |
| --- | --- |
| `connect()` | **연결 시도 및 재시도 처리** (3번 시도 후 실패 시 `ConnectionError` 발생) |
| `deliver_event()` | **비즈니스 로직을 캡슐화** (연결 및 데이터 전송) + **예외 로깅 후 재전달** |
| `send()` | **예외를 직접 처리하지 않음** (상위 메서드에서 처리) |

🚀 **핵심 아이디어**

- **연결 관련 예외**는 `connect()`에서 해결하려고 노력한 후, 실패하면 던짐
- **데이터 문제(`ValueError`)**는 `deliver_event()`에서 감지하여 로깅 후 예외 발생
- `send()`는 단순한 데이터 전송만 수행하고, 예외 처리는 하지 않음
