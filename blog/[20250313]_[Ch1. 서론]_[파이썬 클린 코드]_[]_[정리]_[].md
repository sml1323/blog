# Chapter 1. 서론
<details>
  <summary>`attribute` vs. `property`의 차이</summary>

| 개념 | 설명 | 예시 |
| --- | --- | --- |
| **Attribute (일반 속성)** | 클래스의 **변수(필드)**로, 값이 직접 저장됨. | `obj.name = "Alice"` |
| **Property (프로퍼티)** | 속성처럼 보이지만, **getter, setter 등을 활용한 메서드 기반 속성** | `obj.age = 30 # 내부적으로 setter 메서드 실행` |

### Getter, Setter 사용 예제

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self._age = age  # 진짜 값은 _age에 저장 (보호를 위해 _ 사용)

    @property
    def age(self):
        """getter 역할: 값을 가져올 때 호출됨"""
        print("getter 호출됨")
        return self._age

    @age.setter
    def age(self, value):
        """setter 역할: 값을 변경할 때 호출됨"""
        print("setter 호출됨")
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person("Alice", 30)

print(p.age)  # getter 호출됨 → 30
p.age = 35    # setter 호출됨
print(p.age)  # getter 호출됨 → 35
```

---

## ✅ `@property`를 사용하는 4가지 주요 장점

### 1️⃣ 캡슐화(Encapsulation) - 내부 구현을 숨길 수 있음

일반 속성(`self.age`)을 직접 사용하면, 속성의 내부 구조가 변경될 때 코드를 수정해야 할 수도 있음.

#### ❌ 일반 속성을 사용하면?

```python
class Person:
    def __init__(self, age):
        self.age = age  # 그냥 속성

p = Person(30)
print(p.age)  # 30
p.age = -5  # 잘못된 값이 들어감! (문제 발생)
```

위 코드에서는 `p.age = -5`처럼 **잘못된 값**을 막을 방법이 없음.

---

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, age):
        self._age = age  # 실제 값은 _age에 저장

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person(30)
p.age = -5  # ❌ ValueError 발생! (잘못된 값 차단)
```

✔️ **외부에서 직접 `self._age`에 접근하지 못하게 하고, setter를 통해 제어하는 방식!**

---

### 2️⃣ 인터페이스 유지 - 내부 구현을 바꿔도 외부 코드는 그대로 유지됨

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, birth_year):
        self._birth_year = birth_year  # 출생 연도를 저장

    @property
    def age(self):
        """현재 연도(2024)에서 출생 연도를 빼서 나이 계산"""
        return 2024 - self._birth_year

p = Person(1994)
print(p.age)  # 30  (출생 연도 기반 계산)
```

✔️ **속성 이름(`age`)을 그대로 유지하면서 내부 구현을 바꿀 수 있음!**

---

### 3️⃣ 동적 계산 가능 (Lazy Evaluation)

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        """넓이를 매번 계산하여 반환"""
        return self.width * self.height

r = Rectangle(5, 10)
print(r.area)  # 50  (속성처럼 보이지만 실제로는 메서드 실행)
```

✔️ **데이터를 저장하지 않고, 필요할 때마다 계산할 때 유용!**

---

### 4️⃣ 읽기 전용 속성 만들기 가능 (Setter 없이 Getter만 사용)

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def diameter(self):
        """지름은 반지름의 2배이며, 변경할 수 없음"""
        return self._radius * 2

c = Circle(10)
print(c.diameter)  # 20
c.diameter = 30  # ❌ AttributeError: can't set attribute (setter가 없으므로 수정 불가)
```

✔️ **읽기 전용 속성이 필요할 때 getter만 사용하면 됨.**

## 최종 정리

| 장점 | 설명 |
| --- | --- |
| 1️⃣ 캡슐화(Encapsulation) | 내부 속성을 보호하고, setter를 통해 제어 가능 |
| 2️⃣ 인터페이스 유지 | 내부 구현이 바뀌어도 외부 코드 수정 없이 유지 가능 |
| 3️⃣ 동적 계산 | 속성을 저장하지 않고, 필요할 때마다 계산 가능 |
| 4️⃣ 읽기 전용 속성 | setter 없이 getter만 사용하여 변경 불가능하게 만들 수 있음 |

## 01. 클린 코드

- 클린코드는 다른 엔지니어가 코드를 읽고 유지 관리할 수 있는지 여부에 달려 있음.
- 유지보수성 향상, 지속적인 배포
- 기술부채: 개발팀이 제 시간에 어떤 것을 제공할 수 없어서 코드를 수정하고 리팩토링하기 위해 멈추는 것
- 좋은 코드 레이아웃의 핵심은 **일관성** → 구조화 → 가독성 상승

## 02. 문서화 - Documentation

### 코드 주석 - Code Comments

- 가능한 적은 주석을 사용하는 것이 목표. 좋은 코드는 **코드 자체가 문서화**되어 있어야 함.

---

### Docstring과 Annotation

```python
@dataclass
class Point:
    lat: float
    long: float

def locate(latitude: float, longitude: float) -> Point:
    """맵에서 좌표에 해당하는 객체를 검색"""
```

- Docstring: 함수의 설명 제공
- Annotation: 변수 타입을 명확히 하여 코드 가독성 및 유지보수성 향상

---

## 🎯 결론: **그냥 속성 쓰면 안 돼?**

- ✅ 단순한 값 저장이면 **그냥 속성(attribute)** 사용.
- ✅ **유효성 검사, 동적 계산, 인터페이스 유지** 등이 필요하면 **`@property` 사용**.

✔️ **코드 유지보수성과 가독성을 고려해 선택!**
