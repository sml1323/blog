# Chapter 1. 서론

<details>
  <summary>`attribute` vs. `property`의 차이</summary>

| 개념                      | 설명                                                         | 예시                                                        |
| ------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| **Attribute (일반 속성)** | 클래스의 **변수(필드)**로, 값이 직접 저장됨.               | `obj.name = "Alice"`                                        |
| **Property (프로퍼티)**   | 속성처럼 보이지만, **getter, setter 등을 활용한 메서드 기반 속성** | `obj.age = 30  # 내부적으로 setter 메서드 실행`              |

### Getter, Setter 사용 예제

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self._age = age  # 진짜 값은 _age에 저장 (보호를 위해 _ 사용)

    @property
    def age(self):
        """getter 역할: 값을 가져올 때 호출됨"""
        print("getter 호출됨")
        return self._age

    @age.setter
    def age(self, value):
        """setter 역할: 값을 변경할 때 호출됨"""
        print("setter 호출됨")
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person("Alice", 30)

print(p.age)  # getter 호출됨 → 30
p.age = 35    # setter 호출됨
print(p.age)  # getter 호출됨 → 35
```

---

## ✅ `@property`를 사용하는 4가지 주요 장점

### 1️⃣ 캡슐화 (Encapsulation) - 내부 구현을 숨길 수 있음

일반 속성(`self.age`)을 직접 사용하면, 속성의 내부 구조가 변경될 때 코드를 수정해야 할 수도 있음.

#### ❌ 일반 속성을 사용하면?

```python
class Person:
    def __init__(self, age):
        self.age = age  # 그냥 속성

p = Person(30)
print(p.age)  # 30
p.age = -5    # 잘못된 값이 들어감! (문제 발생)
```

위 코드에서는 `p.age = -5`처럼 **잘못된 값**을 막을 방법이 없음.

---

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, age):
        self._age = age  # 실제 값은 _age에 저장

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("나이는 0 이상이어야 합니다!")
        self._age = value

p = Person(30)
p.age = -5  # ❌ ValueError 발생! (잘못된 값 차단)
```

✔️ **외부에서 직접 `self._age`에 접근하지 못하게 하고, setter를 통해 제어하는 방식!**

---

### 2️⃣ 인터페이스 유지 - 내부 구현을 바꿔도 외부 코드는 그대로 유지됨

#### ✅ `@property`를 사용하면?

```python
class Person:
    def __init__(self, birth_year):
        self._birth_year = birth_year  # 출생 연도를 저장

    @property
    def age(self):
        """현재 연도(2024)에서 출생 연도를 빼서 나이 계산"""
        return 2024 - self._birth_year

p = Person(1994)
print(p.age)  # 30  (출생 연도 기반 계산)
```

✔️ **속성 이름(`age`)을 그대로 유지하면서 내부 구현을 바꿀 수 있음!**

---

### 3️⃣ 동적 계산 가능 (Lazy Evaluation)

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        """넓이를 매번 계산하여 반환"""
        return self.width * self.height

r = Rectangle(5, 10)
print(r.area)  # 50  (속성처럼 보이지만 실제로는 메서드 실행)
```

✔️ **데이터를 저장하지 않고, 필요할 때마다 계산할 때 유용!**

---

### 4️⃣ 읽기 전용 속성 만들기 가능 (Setter 없이 Getter만 사용)

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def diameter(self):
        """지름은 반지름의 2배이며, 변경할 수 없음"""
        return self._radius * 2

c = Circle(10)
print(c.diameter)  # 20
c.diameter = 30    # ❌ AttributeError: can't set attribute (setter가 없으므로 수정 불가)
```

✔️ **읽기 전용 속성이 필요할 때 getter만 사용하면 됨.**

---

## 최종 정리

| 장점                 | 설명                                     |
| -------------------- | ---------------------------------------- |
| **캡슐화**           | 내부 속성을 보호하고, setter를 통해 제어 가능 |
| **인터페이스 유지**  | 내부 구현이 바뀌어도 외부 코드 수정 없이 유지 가능 |
| **동적 계산**        | 속성을 저장하지 않고, 필요할 때마다 계산 가능 |
| **읽기 전용 속성**   | setter 없이 getter만 사용하여 변경 불가능하게 만들 수 있음 |

# 01. 클린 코드

- 클린 코드는 다른 엔지니어가 코드를 읽고 유지 관리할 수 있는지 여부에 달려있다.
- 유지보수성 향상, 지속적인 배포
- **기술부채:** 개발팀이 제 시간에 어떤 것을 제공할 수 없어서 코드를 수정하고 리팩토링하기 위해 멈추는 상황
- **Agile ↔ Rigid:** 좋은 코드 레이아웃의 핵심은 일관성 → 구조화 → 가독성 상승
- 말의 위치가 무작위이면 체스 마스터들도 일반인과 다름 없으나, 논리적 순서를 따르면 체스 마스터들이 압도적으로 우수함.

# 02. 문서화 - Documentation

## 코드 주석 - Code Comments

- 가능한 적은 주석을 사용하는 것을 목표로 해야 한다. 좋은 코드는 코드 자체가 문서화 되어있기 때문이다.
- 즉, 주석을 사용하는 것은 코드를 올바르게 작성하지 않았다는 징후이다.
- 문서화는 코드 설계 방식이나 아키텍쳐를 설명하는 것을 의미하며, 이는 긍정적인 효과를 가져온다.

## Docstring

- **Docstring**은 소스코드에 포함된 문서(Documention)라고 할 수 있다. → 이유가 아니라 설명이다.
- Docstring은 코멘트가 아니라 **문서**이다.
- Docstring을 추가하려고 노력하는 것은 좋은 습관이다.
- 파이썬은 동적인 데이터타입을 갖기 때문에, 파이썬 함수의 파라미터 값으로 어떤 데이터 타입도 취할 수 있다. 이런 경우 docstring을 추가하는 것이 도움이 된다.

## 어노테이션 - Annotation

- 코드 사용자에게 함수 인자로 어떤 값이 와야 하는지 힌트를 주는 것

예제: 변수의 예상 타입 지정

```python
from dataclasses import dataclass

@dataclass
class Point:
    lat: float
    long: float

def locate(latitude: float, longitude: float) -> Point:
    """맵에서 좌표에 해당하는 객체를 검색"""
    # Point는 사용자 정의 클래스이므로 클래스 인스턴스를 반환한다.
```

- 예를 들어, **`def launch_task(delay_in_seconds):`**의 경우 많은 정보를 담고 있는 것 같지만, 충분한 정보를 제공하지 못하고 있다. 허용 가능한 지연시간은 몇 초인지, 분수를 사용해도 되는지 등의 정보가 없다.
- `Seconds = float`  
- **`def launch_task(delay: Seconds):`**  
  이 경우 `Seconds` 어노테이션을 사용하여 시간을 어떻게 해석할지에 대해 작은 추상화를 한 것이다.
- 어노테이션을 사용할 경우, `__annotations__`라는 특수한 attribute가 생성된다.

```python
print(locate.__annotations__)
# {'latitude': <class 'float'>, 'longitude': <class 'float'>, 'return': <class '__main__.Point'>}
```

- 충분한 정보를 제공하기 위해 해당 데이터 구조를 따로 정의하여 명시적으로 알려줄 수도 있다.

```python
from typing import Tuple
Client = Tuple[int, str]

def process_clients(clients: list[Client]):
    ...
```

- dataclass 데코레이터를 사용하면 초기화하지 않고 인스턴스 속성으로 만들 수 있다:

```python
from dataclasses import dataclass

@dataclass
class Point:
    lat: float
    long: float
```

- **docstring**과 **annotation**은 서로 보완적인 관계이다.

### 데이터 유효성 검사 및 사전 값 반환 함수 예제

```python

    if response["status"] != 200:
        raise ValueError
    return {"data": response["payload"]}
```

위의 경우, `response` 객체의 올바른 인스턴스 형태와 결과 인스턴스 형태가 명확하지 않다.

```python
def data_from_response(response: dict) -> dict:

```

# Ch2. Pythonic 코드

## 자체 시퀀스 생성

### 매직 메서드: `__getitem__`

- 리스트 슬라이싱(`list[1:3]`, `list[::]`, `list[-1]`, `list[1:7:2]` 등)은 내부적으로 `slice` 함수를 호출하는 것과 같다. 예를 들어:
  
  ```python
  interval = slice(1, 7, 2)
  my_number[interval]
  ```

- 위 기능은 매직 메서드 덕분에 동작한다.

### `__getitem__` 매직 메서드란?

`__getitem__`은 객체에서 `[]`(대괄호)로 값을 가져올 때 호출되는 매직 메서드이다.

예:

```python
my_list = [10, 20, 30, 40, 50]
print(my_list[2])  # 30 (== my_list.__getitem__(2))
```

즉, `my_list[2]`는 실제로 `my_list.__getitem__(2)`를 호출하는 것과 같다.

### 직접 만든 클래스에서 `__getitem__` 구현하기

```python
class Items:
    def __init__(self, *values):
        self._values = list(values)  # 내부 리스트 저장

    def __len__(self):
        return len(self._values)  # 길이 반환

    def __getitem__(self, item):
        return self._values.__getitem__(item)  # 내부 리스트의 __getitem__ 호출

nums = Items(10, 20, 30, 40, 50)
print(nums[2])  # 30 (== nums.__getitem__(2))
```

### 리스트 슬라이싱과 `slice` 객체

```python
my_list = [10, 20, 30, 40, 50]
print(my_list[1:4])  # [20, 30, 40]
```

위 코드는 내부적으로 `my_list.__getitem__(slice(1, 4))`를 호출한다.

```python
nums = Items(10, 20, 30, 40, 50)
print(nums[1:4])  # [20, 30, 40]
```

즉, `nums[1:4]`는 내부적으로 `nums.__getitem__(slice(1, 4))`가 호출되고, 내부 리스트의 `__getitem__`이 실행되어 `[20, 30, 40]`을 반환한다.

### `slice` 객체 직접 사용하기

```python
interval = slice(1, 4)
print(my_list[interval])  # [20, 30, 40]
```

즉, `my_list[1:4]`는 `slice(1, 4)` 객체를 생성해서 `__getitem__`에 넘기는 것과 같다.

### 정리

- `__getitem__`은 객체에서 `[]` 연산자를 처리하는 매직 메서드이다.
- 슬라이싱(`obj[start:end:step]`)을 하면 `slice(start, end, step)` 객체가 `__getitem__`에 전달된다.
- `Items` 클래스는 내부 리스트 `_values`의 `__getitem__`을 그대로 호출하여 리스트처럼 동작하게 한다.

## 컨텍스트 관리자 (Context Manager)

- 사전 조건과 사후 조건이 있는 코드, 즉 작업 전후에 실행되는 코드를 작성할 때 사용한다.

예:

```python
fd = open(filename)
try:
    process_file(fd)
finally:
    fd.close()
```

이를 Pythonic하게 작성하면 다음과 같다:

```python
with open(filename) as fd:
    process_file(fd)
```

- `with` 문은 컨텍스트 관리자로 진입하며, `open` 함수는 컨텍스트 관리자를 구현하여 예외가 발생한 경우에도 파일을 자동으로 닫는다.
- 컨텍스트 관리자는 `__enter__`와 `__exit__` 두 개의 매직 메서드로 구성된다.

## 컴프리헨션 (Comprehension) 과 할당 표현식

단일 명령어로 데이터 구조를 생성하려면 컴프리헨션을 사용하는 것이 좋다.

예:

```python
numbers = []
for i in range(10):
    numbers.append(run_calculation(i))
```

위 코드는 다음과 같이 작성할 수 있다:

```python
numbers = [run_calculation(i) for i in range(10)]
```

이렇게 작성된 코드는 일반적으로 반복문에서 `append`를 호출하는 것보다 성능이 좋다.

또 다른 예:

```python
def collect_account_ids_from_arns(arns):
    matched_arns = filter(None, (re.match(ARN_REGEX, arn) for arn in arns))
    return {m.groupdict()["account_id"] for m in matched_arns}
```

## Property, Attribute, 객체 메서드의 다른 타입들

- 파이썬에서는 모든 객체의 속성과 함수는 기본적으로 public이다.
- 접근 제어를 위해 네이밍 컨벤션을 사용한다:
  - **private**: 밑줄 한 개로 시작 (`_age`, `_year` 등)
  - **protected**: 밑줄 두 개로 시작 (`__age`, `__year` 등)

### 파이썬에서의 밑줄

- 이중 밑줄을 사용하면 파이썬은 **이름 맹글링(name mangling)**을 수행하여, 변수 이름을 “_<class_name>__<attribute-name>” 형태로 변경한다.
- 예: `Connect` 클래스의 `__timeout` 속성은 `conn._Connect__timeout`으로 접근할 수 있다.
- 단, 이중 밑줄 사용은 Pythonic하지 않다.

### 프로퍼티 (Property)

- 예를 들어, 지리 시스템에서 위도와 경도는 특정 범위 내에서만 유효하므로 프로퍼티를 사용할 수 있다.

```python
class Coordinate:
    def __init__(self, lat: float, long: float) -> None:
        self._latitude = None
        self._longitude = None
        self.latitude = lat    # setter를 통해 값 검증
        self.longitude = long

    @property
    def latitude(self) -> float:
        return self._latitude

    @latitude.setter
    def latitude(self, lat_value: float) -> None:
        if lat_value not in range(-90, 91):
            raise ValueError(f"유효하지 않은 위도 값: {lat_value}")
        self._latitude = lat_value

    @property
    def longitude(self) -> float:
        return self._longitude

    @longitude.setter
    def longitude(self, long_value: float) -> None:
        if long_value not in range(-180, 181):
            raise ValueError(f"유효하지 않은 경도 값: {long_value}")
        self._longitude = long_value
```

- 프로퍼티는 **명령-쿼리 분리 원칙(command and query separation)** 을 따르기 위한 좋은 방법이다.
  - 메서드는 한 가지 작업만 수행해야 하며, 작업 후 상태를 확인하려면 메서드를 분리해야 한다.

### 보다 간결한 구문으로 클래스 만들기

- 파이썬에는 객체의 값을 초기화하는 보일러플레이트 코드가 존재한다:

  ```python
  def __init__(self, x, y, ...):
      self.x = x
      self.y = y
  ```

- `dataclasses` 모듈을 사용하면 `__init__` 메서드를 자동 생성하므로 이를 단순화할 수 있다.

- mutable 데이터 타입(예: `list`)의 경우, 기본값으로 직접 할당하면 모든 인스턴스가 같은 객체를 참조하게 되므로 `default_factory`를 사용해야 한다.

  ```python
  from dataclasses import dataclass, field

  @dataclass
  class Point:
      lat: float
      long: float
      friends: list = field(default_factory=list)
  ```

## **R-Trie 자료구조**

- **R**: radix  
  일부 기본 요소(base R)에 대한 인덱싱된 트리

- **radix**: 주어진 데이터를 구성하는 기본 요소  
  (문자열 검색의 경우 알파벳이 기본 요소)

- 문자열에 대한 빠른 검색을 위해 사용된다.
- 이 자료구조는 현재의 문자를 나타내는 `value`와 다음 문자를 나타내는 `next_` 배열을 가진다.
  - 예: a로 시작하는 단어 집합의 경우, `value`에 a가 저장되고, `next_`에는 이어지는 문자들에 대한 R-Trie 노드 참조가 저장된다.

```python
from typing import List
from dataclasses import dataclass, field

R = 26

@dataclass
class RTrieNode:
    size = R
    value: int
    next_: List["RTrieNode"] = field(default_factory=lambda: [None] * R)

    def __post_init__(self):
        if len(self.next_) != self.size:
            raise ValueError("리스트(next_)의 길이가 유효하지 않음")
```

- 주의: `next_: List["RTrieNode"] = []`처럼 초기화하면 모든 인스턴스가 동일한 리스트를 참조하게 되므로 `default_factory`를 사용한다.
- `default_factory`에는 함수 객체를 전달해야 한다.

## 이터러블 객체 (Iterable Objects)

- list, tuple, set, dict 등은 for 루프를 통해 반복할 수 있는 객체이다.
- 엄밀히 말하면, `__iter__` 매직 메서드를 구현한 객체이며, 이터레이터는 `__next__` 매직 메서드를 구현한 객체이다.

### 이터러블 객체 만들기

#### 날짜를 하루 간격으로 반복하는 객체 (직접 이터레이터 구현)

```python
from datetime import timedelta, datetime

class DateRangeIterable:
    """자체 이터레이터 메서드를 가지고 있는 이터러블"""
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date
        self._present_day = start_date  

    def __iter__(self):
        return self

    def __next__(self): 
        if self._present_day >= self.end_date:
            raise StopIteration
        today = self._present_day
        self._present_day += timedelta(days=1)
        return today

for day in DateRangeIterable(datetime(2019, 1, 1), datetime(2019, 1, 5)):
    print(day)
```

출력 예:
```
2019-01-01 00:00:00
2019-01-02 00:00:00
2019-01-03 00:00:00
2019-01-04 00:00:00
```

- 이 예제는 한 번 순회하면 내부 상태가 끝에 도달하여 이후 호출 시 `StopIteration` 예외가 발생한다.
- 두 개 이상의 for 루프에서 사용하면 첫 번째 루프만 동작하고 두 번째 루프는 동작하지 않는다.

#### 제너레이터를 사용한 이터러블

```python
class DateRangeIterable:
    """제너레이터를 사용한 이터러블"""
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date

    def __iter__(self):
        present_day = self.start_date
        while present_day < self.end_date:
            yield present_day
            present_day += timedelta(days=1)

# 여러 번 사용 가능!
dates = DateRangeIterable(datetime(2019, 1, 1), datetime(2019, 1, 5))

for day in dates:
    print(day)

print("두 번째 루프 실행!")

for day in dates:
    print(day)
```

## 시퀀스 만들기

- 시퀀스는 `__len__`과 `__getitem__`을 구현하며, 인덱싱이 가능한 객체이다.
- 이터러블은 메모리 사용은 적지만 n번째 요소에 접근 시 시간복잡도는 O(n)이 될 수 있다.
- 시퀀스로 구현하면 메모리 사용량은 증가하지만 인덱싱은 O(1) 시간복잡도로 가능하다.

```python
from datetime import timedelta, datetime

class DateRangeSequence:
    def __init__(self, start_date, end_date):
        self.start_date = start_date
        self.end_date = end_date
        self._range = self._create_range()
    
    def _create_range(self):
        days = []
        current_day = self.start_date
        while current_day < self.end_date:
            days.append(current_day)
            current_day += timedelta(days=1)
        return days
    
    def __getitem__(self, day_no):
        return self._range[day_no]
    
    def __len__(self):
        return len(self._range)

s1 = DateRangeSequence(datetime(2021, 1, 1), datetime(2021, 1, 5))
for day in s1:
    print(day)
    
print(s1[3])
```

출력 예:
```
2021-01-01 00:00:00
2021-01-02 00:00:00
2021-01-03 00:00:00
2021-01-04 00:00:00
2021-01-04 00:00:00
```

- 이터러블과 시퀀스는 메모리와 CPU 사이의 트레이드오프 관계이다.

## 컨테이너 객체

- 컨테이너는 `__contains__` 메서드를 구현한 객체로, `in` 키워드가 호출될 때 사용된다.

```python
# element in container -> container.__contains__(element)
```

- 예를 들어, 다음 함수는 직관적이지 않다:

```python
def mark_coordinate(grid, coord):
    if 0 <= coord.x < grid.width and 0 <= coord.y < grid.height:
        grid[coord] = MARKED
```

- 컴포지션 패턴을 사용하여 Grid의 일부 기능을 Boundaries 클래스에 위임하는 예제:

```python
class Boundaries:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def __contains__(self, coord):
        x, y = coord
        return 0 <= x < self.width and 0 <= y < self.height

class Grid:
    def __init__(self, width, height):
        self.width = width
        self.height = height
        self.limits = Boundaries(width, height)
    
    def __contains__(self, coord):
        return coord in self.limits

def mark_coordinate(grid, coord):
    if coord in grid:
        grid[coord] = MARKED
```

## 객체의 동적인 속성

- `__getattr__` 매직 메서드를 사용하면 존재하지 않는 속성에 접근할 때의 행동을 제어할 수 있다.
- 객체의 `<myobject>.<myattribute>` 접근 시, 파이썬은 먼저 `__dict__`에서 해당 속성을 찾고, 없으면 `__getattr__`을 호출한다.

```python
class DynamicAttributes:
    def __init__(self, attribute):
        self.attribute = attribute

    def __getattr__(self, attr):
        if attr.startswith("fallback_"):
            name = attr.replace("fallback_", "")
            return f"[fallback resolved] {name}"
        raise AttributeError(f"{self.__class__.__name__}에는 {attr} 속성이 없습니다.")

dyn = DynamicAttributes("value")
print(dyn.attribute)       # 일반 속성 접근
print(dyn.fallback_test)   # __getattr__ 실행 -> "[fallback resolved] test"

# __dict__를 직접 수정하면 __getattr__이 호출되지 않는다.
dyn.__dict__["fallback_test"] = "new value"

print(getattr(dyn, "fallback_test"))   # "new value"
print(getattr(dyn, "fallback_test2"))  # "[fallback resolved] test2"
```

> **주의:** `__getattr__`을 사용할 경우, 존재하지 않는 속성에 접근할 때는 반드시 `AttributeError`를 발생시켜야 한다.

## 호출형 객체 (Callable)

- 객체를 함수처럼 호출하면 `__call__` 매직 메서드가 호출된다.
- 예제: 동일한 파라미터 값으로 몇 번 호출되었는지 카운트

```python
from collections import defaultdict

class CallCount:
    def __init__(self):
        self._counts = defaultdict(int)

    def __call__(self, argument):
        self._counts[argument] += 1
        return self._counts[argument]
    
cc = CallCount()
print(cc(1))  # 1
print(cc(1))  # 2
print(cc(2))  # 1
```

## 파이썬에서 유의할 점

### 변경 가능한(mutable) 파라미터의 기본 값

- 변경 가능한 객체를 함수의 기본 인자로 사용하면 안 된다.

```python
def wrong_user_display(user_metadata: dict = {"name": "John", "age": 30}):
    name = user_metadata.pop("name")
    age = user_metadata.pop("age")
    return f"{name} is {age} years old"
```

- 위와 같은 코드는 처음 호출 시만 정상 동작한다.

#### 해결 방법

```python
def wrong_user_display(user_metadata: dict = None):
    user_metadata = user_metadata or {"name": "John", "age": 30}
    name = user_metadata.pop("name")
    age = user_metadata.pop("age")
    return f"{name} is {age} years old"
```

### 내장(built-in) 타입 확장

- 예를 들어, 특정 인덱스의 아이템에 접근할 때 접두어를 붙여 문자열로 반환하는 사용자 정의 리스트:

```python
class BadList(list):
    def __getitem__(self, index):
        value = super().__getitem__(index)
        prefix = "even" if index % 2 == 0 else "odd"
        return f"Value at {prefix} is {value}"

bl = BadList((0, 1, 2, 3, 4, 5))
print(bl[0])
print(bl[1])
print("".join(bl))
```

- 위 경우, `join`은 리스트 원소들이 모두 문자열이어야 하므로 숫자형 원소가 있으면 오류가 발생한다.
- `from collections import UserList`를 사용하면 이 문제를 해결할 수 있다.

## 비동기 코드 (Asynchronous Code)에 대한 간략한 소개

- 비동기 프로그래밍의 기본 아이디어는 중지(suspend) 가능한 코드가 있을 때, 그 동안 다른 코드를 실행하는 것이다. 주로 I/O 작업 시 사용된다.
- 동기적 코드에서는 기능이 종료될 때까지 기다리지만, 비동기 코드는 이벤트 루프에 의해 스케줄링되어 같은 스레드 내에서 다른 작업이 수행된다.

비동기 프로그래밍 과정:
1. 일련의 코루틴을 만들고 이벤트 루프에 추가한다.
2. 이벤트 루프가 시작되면, 코루틴 중 하나를 선택하여 실행한다.
3. 코루틴 중 하나가 I/O 작업을 실행하면, 이벤트 루프에 제어권을 넘긴다.
4. 이벤트 루프는 I/O 작업이 진행되는 동안 다른 코루틴을 실행한다.
5. I/O 작업이 종료되면, 중지된 코루틴은 마지막 지점에서 다시 실행된다.

> 함수 앞에 `async def`를 사용하고, 코루틴 내부에서 다른 코루틴을 호출할 때는 `await` 키워드를 사용한다. `await`를 사용하면 이벤트 루프에 제어권을 반환할 수 있다.

# Ch3. 좋은 코드의 일반적인 특징

## 계약에 의한 디자인

- **캡슐화와 API 노출**  
  컴포넌트는 기능을 숨겨 캡슐화하고, 클라이언트에게는 **애플리케이션 프로그래밍 인터페이스(API)**를 노출해야 한다.

- **계약에 의한 디자인(Design by Contract)**  
  양측(클라이언트와 제공자)이 동의한 계약을 먼저 정의하고, 계약 위반 시 명시적으로 예외를 발생시킨다.
  - **사전조건(Precondition):** 코드 실행 전에 체크해야 할 조건
  - **사후조건(Postcondition):** 함수 반환값의 유효성 검사
  - **불변식(Invariant):** 함수 실행 동안 일정하게 유지되어야 하는 상태
  - **부작용(Side-effect):** 함수 호출 시 발생하는 부수 효과

---

## 방어적 프로그래밍

> **방어적 프로그래밍(Defensive Programming)**은 계약 위반 시 예외를 발생시키는 대신, 객체나 함수, 메서드가 스스로 유효하지 않은 상태로부터 보호하도록 만드는 것이다.

### 에러 핸들링

- **목적:** 예상되는 에러에 대해 실행을 계속할 수 있는지, 혹은 극복할 수 없는 오류로 프로그램을 중단할지 결정하는 것.
  - **값 대체(Value Substitution):** 잘못된 결과를 합리적인 다른 값으로 대체
  - **에러 로깅:** 오류 발생 시 기록
  - **에러 처리:** 오류 발생에 대한 적절한 대응

### 예외 처리

- **목표:** 예외 상황을 명확하게 알리고, 원래의 비즈니스 로직에 따라 흐름을 유지
- **추상화 수준:** 각 함수는 자신이 캡슐화한 로직에 해당하는 예외만 처리해야 한다.

---

## 예제: `DataTransport` 클래스

다음 코드는 다양한 수준의 예외를 처리하는 예시입니다.

```python
class DataTransport:
    """다양한 수준의 예외를 처리하는 예제"""
    _RETRY_BACKOFF: int = 5   # 재시도 시 대기 시간 (초)
    _RETRY_TIMES: int = 3     # 재시도 횟수

    def __init__(self, connector: Connector) -> None:
        self._connector = connector
        self.connection = None

    def deliver_event(self, event: Event):
        try: 
            self.connect()           # 서버에 연결 시도
            data = event.decode()    # 이벤트 데이터를 디코딩
            self.send(data)          # 데이터 전송
        except ConnectionError as e:
            logger.info("커넥션 오류 발견: %s", e)
            raise  # 예외를 상위 코드로 전달
        except ValueError as e:
            logger.error("%r 이벤트에 잘못된 데이터 포함: %s", event, e)
            raise  # 잘못된 데이터일 경우 예외 발생

    def connect(self):
        for _ in range(self._RETRY_TIMES):  # 최대 3번 재시도
            try:
                self.connection = self._connector.connect()
            except ConnectionError as e:
                logger.info("%s: 새로운 커넥션 시도 %is", e, self._RETRY_BACKOFF)
                time.sleep(self._RETRY_BACKOFF)
            else:
                return self.connection  # 연결 성공 시 반환
        raise ConnectionError(f"{self._RETRY_TIMES} 번의 재시도 모두 실패")

    def send(self, data: bytes):
        return self.connection.send(data)
```

### 코드 설명

1. **클래스 개요**  
   `DataTransport` 클래스는 데이터 전송을 담당하며,  
   - 서버 연결 시도
   - 이벤트 데이터를 디코딩 후 전송
   - 연결 오류 발생 시 재시도 후 실패 시 예외 발생  
   등의 작업을 수행합니다.

2. **주요 속성**
   - `_RETRY_BACKOFF`: 연결 실패 시 대기 시간 (5초)
   - `_RETRY_TIMES`: 재시도 횟수 (3번)

3. **`__init__` 생성자**
   - `self._connector`: 연결을 시도할 때 사용할 `Connector` 객체
   - `self.connection`: 실제 연결 객체 (초기에는 `None`)

4. **`deliver_envet()` 메서드**
   - **동작 과정:**
     1. `connect()`를 호출하여 서버에 연결
     2. `event.decode()`를 통해 이벤트 데이터를 디코딩
     3. `send(data)`를 호출하여 데이터를 전송
   - **예외 처리:**
     - `ConnectionError` 발생 시: 로깅 후 예외를 재전달
     - `ValueError` 발생 시: 잘못된 데이터임을 로깅 후 예외 발생

5. **`connect()` 메서드**
   - 최대 `_RETRY_TIMES`(3번) 동안 연결을 시도하고, 실패하면 재시도 전에 `_RETRY_BACKOFF`(5초) 대기.
   - 3번의 재시도 후에도 연결 실패 시 `ConnectionError` 예외 발생

6. **`send()` 메서드**
   - 단순히 연결된 `self.connection`을 통해 데이터를 전송하며, 예외 처리는 상위 메서드(`deliver_envet()`)에서 담당.

### 예외 처리의 추상화 수준

| 메서드              | 예외 처리 내용                                                    |
| ------------------- | ----------------------------------------------------------------- |
| `connect()`         | 연결 시도 및 재시도 → 3번 실패 시 `ConnectionError` 발생             |
| `deliver_envet()`   | 비즈니스 로직 캡슐화: 연결, 디코딩, 전송 → 예외 발생 시 로깅 후 재전달    |
| `send()`            | 단순 데이터 전송 (예외 처리는 하지 않음; 상위에서 처리)               |

**핵심 아이디어**

- **연결 관련 예외:** `connect()` 메서드에서 재시도 후 실패하면 예외를 발생시켜 상위 로직에서 처리하도록 함.
- **데이터 관련 예외:** `event.decode()` 과정에서 문제가 발생하면 `ValueError`가 발생하고, 이를 로깅 후 상위로 전달.
- **추상화:** 각 메서드는 자신이 책임지는 로직과 예외만 처리하며, 불필요한 예외의 혼합을 피한다.
